# หน้า Data Ingestion (`/ingestion`) — คำอธิบายทีละส่วน (สำหรับนำเสนออาจารย์)

> ทุกข้อความด้านล่างตรวจจากโค้ดจริง อ้างอิงเป็น `ไฟล์:บรรทัด` ถ้าตรวจไม่พบจะเขียนว่า "ตรวจไม่พบในโค้ด"
> ป้ายกำกับ: 🟢 ข้อมูลจริงจาก Backend | 🟡 ข้อมูลที่คำนวณจากระบบ | 🔴 Mock/Static/ค่าคงที่ฮาร์ดโค้ด | ⚪ UI ที่มีแต่ยังไม่ได้เชื่อมระบบจริง
> คำศัพท์: **HDFS** = ระบบเก็บไฟล์แบบกระจาย (เหมือนไดรฟ์กลางของระบบ) / **Spark** = โปรแกรมประมวลผลข้อมูลขนาดใหญ่ / **Elasticsearch (ES)** = ฐานข้อมูลค้นหา ใช้เก็บบันทึกการรัน / **Kafka** = ท่อส่งข้อความสตรีมแบบเรียลไทม์ / **Delta** = รูปแบบตารางบน HDFS ที่แก้ไข/ย้อนเวอร์ชันได้ / **Quarantine** = ที่กักกันแถวข้อมูลที่ไม่ผ่านเกณฑ์

## 0. สรุปสิ่งที่ต้องรู้ก่อนนำเสนอ (อ่านก่อน!)

หน้านี้ทำงาน "สองสายขนานกัน" ซึ่งเป็นจุดที่คนสับสนง่ายที่สุด:

| สาย | ทำอะไร | เก็บที่ไหน | แสดงผลที่หน้านี้อย่างไร |
|---|---|---|---|
| **A. สายตรวจเบื้องต้นแบบโต้ตอบ (pandas)** `/api/v1/whitebox/*` | อ่านไฟล์ที่อัปโหลดเข้าหน่วยความจำ/ดิสก์ของ API แล้วคำนวณ profile (จำนวนแถว ค่าว่าง ซ้ำ ผิดปกติ) ทันที | ไฟล์ CSV ในโฟลเดอร์ `output_runs` ของคอนเทนเนอร์ API (`whitebox.py:111-114`) + ไฟล์ `workflow_state.json` (`whitebox.py:1214-1224`) | **ส่วน "ผลตรวจข้อมูล" ทั้งหมด** (การ์ดตัวเลข 3 ใบ, ช่องค้นหา) |
| **B. สายท่อข้อมูลจริง (Spark)** `/api/v1/pipeline/ingest/*` | ส่งไฟล์เข้า HDFS แล้วสั่ง Spark ตรวจคุณภาพ → เขียนตาราง Delta + บันทึก ES | HDFS `/data/raw/...` → `/data/active/...` + `/data/quarantine/...` + `/data/archive/...`; ES index `sdoqap_runs`, `sdoqap_quality_runs`, `sdoqap_pipeline_runs` | แสดงแค่บรรทัดเดียว "สถานะรอบ: ..." (`RunStatusLine`) — ไม่มีตัวเลขผลตรวจ Spark ในหน้านี้ |

ข้อค้นพบสำคัญ (พูดตรง ๆ กับอาจารย์ได้):

1. **มี 4 แท็บ แต่ต่อระบบจริงครบ "ไปที่ Spark/HDFS" แค่ 2 แท็บ: "ไฟล์" และ "ฐานข้อมูล (PostgreSQL เท่านั้น)"**
2. **แท็บ "API" ในหน้านี้ ⚪ ไม่ได้เรียก API จริง** — กดปุ่มแล้วเรียก `/whitebox/ingest-source` ซึ่งโค้ดบอกชัดว่า `simulated: True` ไม่เปิดการเชื่อมต่อจริง (`whitebox.py:1607-1613`) ระบบแค่ตรวจข้อมูลชุดเดิมที่โหลดไว้ซ้ำ ส่วน endpoint จริง `/pipeline/ingest/api` ไม่มีปุ่มใดในหน้านี้เรียก (เรียกได้จาก n8n เท่านั้น)
3. **แท็บ "Stream" ⚪ ช่อง Kafka Brokers/Topic/Group ไม่ถูกส่งไปทำงานจริง** — ปุ่มเดียวทำ 2 อย่าง: (ก) สั่งเริ่ม/หยุดสตรีม **Reddit** (subreddits `python,bigdata` ระยะ 40 วินาที ค่าตายตัวที่แก้ไม่ได้ในหน้าจอ) และ (ข) เรียก `/whitebox/ingest-source` แบบจำลอง (`Ingestion.jsx:864-869`) ไม่มี Reddit/Kafka อื่นที่ผู้ใช้กำหนดเองได้
4. **ผลตรวจ (การ์ดสรุป + 3 การ์ด finding) ไม่ใช่ผลจาก Spark** แต่มาจาก pandas ใน API และเปิดหน้าครั้งแรกจะเห็นผลของ **ชุดข้อมูลตัวอย่างที่ติดมากับระบบ** (`dirty_dataset.csv` ~10,100 แถว, `data/evaluation/.../dirty_dataset.csv`) แม้ผู้ใช้ยังไม่ได้นำเข้าอะไรเลย (`Ingestion.jsx:353-355` + `whitebox.py:324-339`)
5. **โค้ดตาย (dead code) จำนวนมากใน `Ingestion.jsx`** — ฟังก์ชัน `handleCsvSubmit`, `handleApiSubmit`, `handleRdbmsSubmit`, `handleDrop`, `handleFileChange`, ตัวติดตามความคืบหน้า Spark (useEffect บรรทัด 403-487), `getPercentage` ถูกประกาศไว้แต่ **ไม่มีส่วนใดใน JSX เรียกใช้** ตัวแปรสถานะ `csvStatus/apiStatus/rdbmsStatus/redditStatus/streamInfo` ไม่ถูกแสดงบนหน้าจอ ตัวแปร `apiMethod`, `apiKey` (ช่อง Bearer Token), `apiInterval`, `redditTopic`, `streamGroup` ไม่ถูกส่งไป backend จริง
6. **ผลตรวจอาจหลอกตา 2 กรณี (อ่านจากโค้ด ยังไม่ได้ทดลองรัน):** (ก) อัปโหลดไฟล์ที่คอลัมน์ไม่ครบ (ไม่มี `student_id, course, score, study_hours`) → การเรียก "ตรวจใหม่" อัตโนมัติหลังอัปโหลดอาจดึง profile ของชุดตัวอย่าง `dirty_dataset.csv` มาทับ (ดูข้อ 3.1 หมายเหตุ) (ข) ดึงข้อมูลจากฐานข้อมูล แล้วการ์ดผลตรวจ **ไม่เปลี่ยน** (ยังเป็น profile เดิม) เพราะ `ingestFromRdbms` ไม่เรียก `setProfilingData`

## 2. ลำดับการไหลของข้อมูล (end-to-end) ของเส้นทางหลัก: อัปโหลดไฟล์

1. ผู้ใช้เปิด `/ingestion` → หน้าเรียก `GET /whitebox/profile` และ `/whitebox/state` เพื่อแสดงผลชุดข้อมูลปัจจุบัน (ค่าเริ่มต้น = ชุดตัวอย่าง) (`Ingestion.jsx:329-355`)
2. ผู้ใช้เลือก/ลากไฟล์ `.csv/.xlsx/.xls` → ระบบเก็บไฟล์ไว้ในหน้าจอ (ยังไม่ส่ง) และเติมชื่อตารางจากชื่อไฟล์ (`stageCsvFile`, `:201-209`)
3. กด **"นำเข้าและตรวจข้อมูล"** → `uploadCsvFile` (`:276-313`) ส่งไฟล์ **ครั้งที่ 1** ไป `POST /whitebox/upload-csv`
4. API อ่านไฟล์ด้วย pandas (CSV หรือ Excel) → ถ้ามีคอลัมน์ครบ 4 ตัวจะบันทึกเป็น `working_dataset.csv` และสลับ "แหล่งข้อมูลปัจจุบัน" เป็น upload → คำนวณ profile ส่งกลับ (`whitebox.py:1532-1590`)
5. หน้าจอแสดงผลตรวจ (การ์ดสรุป + 3 การ์ด) จาก profile นั้น
6. หน้าจอส่งไฟล์เดิม **ครั้งที่ 2** ไป `POST /pipeline/ingest/csv` (`queueInPipeline`, `:213-229`)
7. API ตรวจ: ล็อกอิน/ชื่อตาราง (`validate_table_name`, `validation.py`) → ขนาด ≤ `MAX_UPLOAD_MB` (200MB) (`ingest_guards.py:96-109`) → ไม่ว่างเปล่า → ถ้าเป็น Excel แปลงเป็น CSV (`pipeline.py:324-329`)
8. `land_and_queue` (`pipeline.py:271-303`): คำนวณ SHA-256 ของไฟล์ → ถ้า "ตารางเดียวกัน + ไฟล์เดียวกัน" เคยอยู่ในสถานะ QUEUED/RUNNING/SUCCEEDED จะตอบ `duplicate` ไม่ทำซ้ำ (`run_registry.py:10,42-47`) → ตรวจว่ามีคอลัมน์ primary key ตามที่ลงทะเบียนไว้ → สร้าง `ingest_id` = `วันเวลา-รหัสสุ่ม 8 ตัว` (`run_registry.py:17-18`)
9. เขียนไฟล์เข้า HDFS ที่ `/data/raw/<table>/<ingest_id>/<table>.csv` ผ่าน WebHDFS (ลองใหม่ 5 ครั้งถ้า NameNode อยู่ Safe Mode) (`pipeline.py:194-227`)
10. สร้างเอกสารสถานะ `QUEUED` ใน ES index `sdoqap_runs` (`run_registry.py:50-64`)
11. API สั่ง Spark Trigger Daemon `POST :8099/retry` พร้อมรหัสลับ `X-Trigger-Secret` (`pipeline.py:230-242`); ถ้าเรียก daemon ไม่ได้ → สถานะ `TRIGGER_FAILED` + แจ้ง 503 (`pipeline.py:291-295`)
12. Daemon ใส่คิวต่อ "ตาราง" (ตารางเดียวกันรันทีละงาน งานที่เหลือรอคิว) (`trigger_core.py:53-79`) → ตั้งสถานะ `RUNNING` → รัน `spark-submit spark_quality_engine.py <table> --ingest-id <id>` (`spark_trigger_daemon.py:182-207`, `trigger_core.py:27-41`)
13. Spark อ่าน CSV จาก `/data/raw/<table>/<ingest_id>` → ตรวจคุณภาพ → แถวไม่ผ่านเขียนลง Delta `/data/quarantine/<table>`; แถวผ่าน MERGE (upsert) ลง Delta `/data/active/<table>` (`spark_quality_engine.py:1618-1626, 1705-1740`) → บันทึกผลลง ES (`sdoqap_pipeline_runs`, `sdoqap_quality_runs`)
14. ถ้า quality score ถึงเกณฑ์ → สั่งสร้าง Gold layer อัตโนมัติ (`spark_quality_engine.py:1779-1788`); ย้ายโฟลเดอร์ raw ไปเก็บ `/data/archive/<table>/<ingest_id>` (`:1793-1797`, `run_support.py:25-27`)
15. ถ้ามีแถวถูกกักกัน daemon เรียก AI แก้ไขอัตโนมัติ 1 รอบ แล้วรัน Spark ตรวจซ้ำ (`spark_trigger_daemon.py:137-179, 210-225`)
16. Daemon บันทึกสถานะสุดท้าย `SUCCEEDED` / `FAILED` / `SKIPPED` (รหัสออก 0 / อื่น ๆ / 75) ลง ES (`trigger_core.py:44-50`, `spark_trigger_daemon.py:225`)
17. หน้าจอเรียก `GET /pipeline/runs/{ingest_id}` ซ้ำทุก 5 วินาทีจนสถานะเป็นขั้นสุดท้าย แล้วแสดง "สถานะรอบ: ..." (`useRunStatus.js:6-35`)

> ปลายทางของข้อมูลที่ผ่าน: **HDFS Delta `/data/active/<table>`** — ต้นฉบับถูกเก็บถาวรใน `/data/archive/` — แถวเสีย: `/data/quarantine/<table>` — บันทึกการรัน: Elasticsearch

## 4. การ์ด "แหล่งข้อมูล" (`Ingestion.jsx:704-912`)

### 4.0 แถบเลือกแท็บ 4 แท็บ: ไฟล์ / ฐานข้อมูล / API / Stream (`:707-725`)

- **[แท็บ ไฟล์ | ฐานข้อมูล | API | Stream]** → (1) กดแล้วสลับฟอร์มด้านล่าง (2) ตัวเลือกประเภทแหล่งข้อมูล (3) แค่เปลี่ยนตัวแปร `activeSourceTab` ในหน้า ไม่เรียก API (`:720`) (4) แสดงฟอร์มของแท็บนั้น — รายการแท็บเป็นค่าคงที่ 🔴 (แต่ปุ่มสลับทำงานจริง)
- ค่าเริ่มต้นตอนเปิดหน้า = แท็บ "ไฟล์" (`:131`)

### 4.1 แท็บ "ไฟล์" (สถานะ: 🟢 ต่อระบบจริงครบ — ไปทั้งสาย A และสาย B)

- **[กล่องวางไฟล์ "เลือกไฟล์ หรือลากมาวางที่นี่"]** → (1) คลิกเลือกไฟล์ หรือลากไฟล์มาวาง (รับ `.csv,.xlsx,.xls` ตามตัวเลือกของ input `:745`) (2) พื้นที่รับไฟล์; หลังเลือกแสดงชื่อไฟล์ และ "ขนาด KB · กดเพื่อเปลี่ยนไฟล์" (`:741-742`) (3) `stageCsvFile` (`:201-209`) แค่เก็บไฟล์ในหน้า + ตั้งชื่อตารางจากชื่อไฟล์ (ตัดนามสกุลและแทนอักขระที่ไม่ใช่ a-z A-Z 0-9 _ ด้วย `_`) ไม่ส่งไป server (4) 🟡 ขนาด KB = `csvFile.size / 1024` คำนวณในเบราว์เซอร์ **หมายเหตุ:** การ "ลากวาง" ไม่ตรวจนามสกุลไฟล์ฝั่งหน้าจอ (ฟังก์ชันตรวจนามสกุล `handleDrop` `:499-515` ⚪ เป็นโค้ดตายที่ไม่ได้ผูกกับกล่อง) ถ้าวางไฟล์ผิดชนิดจะไปโดน backend ปฏิเสธเป็นข้อความ "ไม่สามารถอ่านไฟล์ CSV ได้..." (`whitebox.py:55-58`)
- **[ช่อง "ชื่อตาราง"]** → (1) พิมพ์ชื่อตารางปลายทาง (ตัวอักษรอื่นนอกจาก a-z A-Z 0-9 _ ถูกแปลงเป็น `_` ทันที `:757-760`) (2) ชื่อที่จะใช้เป็นชื่อตาราง/โฟลเดอร์ใน HDFS (3) ค่าเริ่มต้น `"student_course_scores"` (`:133`) 🔴 ค่าคงที่ฮาร์ดโค้ด; เมื่อโหลดหน้า ค่านี้จะถูกเขียนทับด้วย `dataset_name` จากสถานะส่วนกลางของ API (`:343`) 🟢 (4) ฝั่ง server ตรวจซ้ำ: อนุญาตแค่ตัวอักษร ตัวเลข `_` `-` ยาว 1-128 (`validation.py`) ถ้าผิดตอบ 400

(RunStatusLine)]** → (1) แสดงอย่างเดียว (2) สถานะของงานตรวจ Spark รอบที่เพิ่งส่ง (3) `useRunStatus` เรียก `GET /pipeline/runs/{ingest_id}` ทุก 5 วินาทีจนสถานะเป็น SUCCEEDED/FAILED/SKIPPED/TRIGGER_FAILED (`useRunStatus.js:3-35`); backend อ่านเอกสาร ES `sdoqap_runs` (`pipeline.py:306-312`, `run_registry.py:38-39`) (4) 🟢 สถานะจริง; คำแปลภาษาไทยเป็นตารางฮาร์ดโค้ด 🔴 (`RunStatusLine.jsx:4-11`): QUEUED "รอคิวตรวจ", RUNNING "กำลังตรวจคุณภาพ", SUCCEEDED "ตรวจเสร็จแล้ว", FAILED "ตรวจไม่สำเร็จ", SKIPPED "ข้าม เพราะมีรอบอื่นกำลังใช้ตารางนี้", TRIGGER_FAILED "สั่งตรวจไม่สำเร็จ"; ก่อนได้ผลครั้งแรกแสดง "กำลังส่งงาน"; อ่านไม่ได้แสดง "ยังอ่านสถานะรอบไม่ได้" แล้วลองใหม่ต่อ **หมายเหตุ:** "ตรวจเสร็จแล้ว" หมายถึงโปรเซส Spark จบด้วยรหัส 0 ไม่ได้บอกคะแนนคุณภาพ — ดูคะแนนที่หน้าอื่น
- **[ข้อความ "เคยนำเข้าไฟล์นี้แล้ว (รอบ …)"]** → แสดงแทน RunStatusLine เมื่อ backend ตอบ `status: "duplicate"` (`:904-905`) 🟢

### 5.1 การ์ดสรุป 4 ใบ (`:937-947`) — แสดงเมื่อมี profile (`profilingData.total_rows != null`, `:675`)

- **[แถวทั้งหมด]** → แสดงจำนวนแถวของชุดข้อมูลปัจจุบัน — 🟢 `profile.total_rows = len(df)` (`whitebox.py:218`)
- **[คอลัมน์]** → จำนวนคอลัมน์ — 🟢 `profile.total_columns` (`whitebox.py:219`)
- **[แถวไม่ซ้ำ]** → 🟡 สูตร `total_rows − duplicate_rows_detected` (`Ingestion.jsx:684`); `duplicate_rows_detected` = จำนวนแถวที่คีย์ผสม `student_id + course + semester` ซ้ำ (นับตัวที่สองเป็นต้นไป) (`whitebox.py:287-292`) — ถ้าไฟล์ไม่มีคอลัมน์เหล่านี้ ค่าซ้ำ = 0 (ไม่ได้ทดสอบ) ทำให้ "แถวไม่ซ้ำ = แถวทั้งหมด" แม้ไฟล์อาจมีแถวซ้ำจริง
- **[ประเด็นที่ต้องดูแล "n / 3"]** → 🟡 `n` = `issueCount` (ดูสูตรข้างบน); **"/ 3" เป็นตัวเลขฮาร์ดโค้ด** (`:944`) 🔴 สีเปลี่ยนเขียว/เหลืองตามว่า n=0 หรือไม่ ถ้าคอลัมน์ไม่ครบจะแสดง "—" (`:942-945`)

### 5.2 กล่องแจ้ง "การตรวจคุณภาพอัตโนมัติรองรับเฉพาะ..." (`:955-959`)

- (1) แสดงอย่างเดียว (2) บอกว่าไฟล์ที่นำเข้าไม่มีคอลัมน์ `student_id, course, score, study_hours` ที่ท่อตรวจคุณภาพแบบโต้ตอบอ่านโดยตรง จึงซ่อนการ์ด finding ทั้ง 3 ใบ (3) คำนวณใน `:677-678` เทียบกับรายการคอลัมน์ฮาร์ดโค้ด `QUALITY_CHECK_COLUMNS` (`:11`, ต้องตรงกับ `QUALITY_ENGINE_COLUMNS` ใน `whitebox.py:64`) (4) 🟡 สำคัญสำหรับการนำเสนอ: **ส่วนตรวจคุณภาพ 3 การ์ดผูกกับข้อมูลนักศึกษา (คะแนน/ชั่วโมงเรียน) โดยเฉพาะ** ไม่ใช่ตรวจได้ทุกตาราง (แต่การรัน Spark ในสาย B รองรับตารางทั่วไปกว่า)

### 5.3 การ์ด finding 3 ใบ (`FindingCard`, `:960-1022`, `:1061-1114`)

โครงสร้างการ์ดเหมือนกัน: หัวข้อ + ชื่อคอลัมน์ / ตัวเลขใหญ่ (จำนวนที่พบ) / 2 บรรทัดสถิติ / "ทำไมถึงเป็นปัญหา" (พับได้) / รายการตัวอย่าง / ช่องติ๊ก "ใช้สร้างเกณฑ์" / ปุ่ม "ดูตัวอย่าง"
สีการ์ด: ไม่มีข้อมูล = "unknown", จำนวน > 0 = สีตามระดับ (critical/warning/info), 0 = ok (`:1062`, 🟡 คำนวณจาก count)

**การ์ด 1 "ค่าว่างและช่วงค่า" (คอลัมน์ `score`)**
- **[ตัวเลขใหญ่ "แถวว่าง"]** → 🟢 `score.null_count` = จำนวนค่าว่างของคอลัมน์ score (`whitebox.py:226`) — **หมายเหตุ:** แม้หัวข้อบอก "และช่วงค่า" แต่ตัวเลขนี้นับเฉพาะ "ค่าว่าง" ไม่นับค่านอกช่วง 0-100 (`:967-968`)
- **[สถิติ "ต่ำสุด → สูงสุด" และ "ค่าว่าง N แถว (x%)"]** → 🟢 `min`,`max` และ `null_count`,`null_rate_pct` จาก profile; `null_rate_pct = null_count / total_rows × 100` ปัดทศนิยม 2 ตำแหน่ง (`whitebox.py:227`) 🟡 (`:970-971`)
- **[ข้อความ "ทำไมถึงเป็นปัญหา"]** → 🔴 คำอธิบายตายตัว "ค่าว่างหรือค่านอกช่วงทำให้ค่าเฉลี่ยและรายงานคลาดเคลื่อน" (`:973`)

**การ์ด 2 "เรคคอร์ดซ้ำ"**
- **[หัวคอลัมน์ `student_id + course + semester`]** → ใช้ชื่อคีย์จาก profile (`tested_composite_key`) ถ้าไม่มีใช้ข้อความสำรอง 🔴 `"student_id + course + semester"` (`:984`) — คีย์ผสมนี้ฮาร์ดโค้ดใน backend ด้วย (`whitebox.py:287`) ผู้ใช้เปลี่ยนไม่ได้จากหน้านี้
- **[ตัวเลขใหญ่ "แถวซ้ำ"]** → 🟢 `duplicate_rows_detected`
- **[สถิติ "ไม่ซ้ำ x / y" และ "ซ้ำ n แถว"]** → 🟡 ไม่ซ้ำ = `total_rows − duplicate_rows`
- **[ข้อความอธิบาย]** → 🔴 ตายตัว (`:993`)

**การ์ด 3 "ค่าผิดปกติ" (คอลัมน์ `study_hours`)**
- **[ตัวเลขใหญ่ "ค่าผิดปกติ"]** → 🟡 `outlier_count` = จำนวนค่านอกช่วง Q1−1.5×IQR ถึง Q3+1.5×IQR (วิธี Tukey/IQR = วิธีมาตรฐานจับค่าโดด) (`whitebox.py:261-267`) — ตัวคูณ 1.5 **ตายตัว** ข้อความในการ์ดเองก็แจ้งว่า "ใช้ตัวคูณ 1.5×IQR ตายตัวเสมอ แม้เปลี่ยนในหน้า Expectations & Alerts แล้วการ์ดนี้จะไม่อัปเดตตาม" (`:1013`) ขณะที่ engine โต้ตอบของหน้า Rules ใช้ค่าตั้ง 3.0 เป็นค่าเริ่มต้น (`whitebox.py:1201, 1307-1308`) → ตัวเลขในการ์ดนี้อาจต่างจากที่หน้า Rules/Pipeline รายงาน
- **[สถิติ "Q1 / Q3" และ "ช่วงปกติ"]** → 🟡 `q1`, `q3`, `lower_fence`, `upper_fence` จาก pandas quantile (`whitebox.py:261-265`)

**ส่วนล่างของทุกการ์ด**
- **[ติ๊ก "ใช้สร้างเกณฑ์"]** → (1) ติ๊กเปิด/ปิดว่าจะให้ปัญหานี้ถูกนำไปสร้างกฎ (2) ตัวเลือกกฎต่อไปหน้า Rules/Pipeline (3) `toggleFinding` (`:315-327`) → `POST /whitebox/state` (ต้องล็อกอิน `whitebox.py:1442`) ส่ง `{selected_findings:{range,duplicate,outlier}}` (4) บันทึกลง `workflow_state.json` (`whitebox.py:1473`) มีผลกับตัวจัดแยกโซน Clean/Review/Quarantine ในสาย A (`whitebox.py:1311-1313`); หน้าจอเปลี่ยนค่าทันที (ไม่รอผล) ถ้าบันทึกไม่สำเร็จ ไม่มีข้อความเตือน (`:324-326`) 🟢 ค่าเก็บจริง; **ไม่มีผลต่อรอบ Spark ที่ส่งไปแล้ว** (ตรวจไม่พบในโค้ดว่า Spark อ่านค่านี้)
- **[ปุ่ม "ดูตัวอย่าง / ซ่อนตัวอย่าง"]** → (1) กดแล้วเปิดรายการตัวอย่างแถวสูงสุด 5 แถว (2) ตัวอย่างแถวที่เป็นปัญหา (3) `handleInspectFindingRows` (`:141-156`) → `GET /whitebox/preview-zone/{zone}?limit=5&error_type=...` ด้วย zone/ชนิด: ค่าว่าง = `quarantine`/"Score", ซ้ำ = `quarantine`/"Duplicate", ผิดปกติ = `review`/"Outlier" (`whitebox.py:1496-1526`) (4) 🟢 แสดง `#id · student_id · course · score=...` เป็นต้น (`renderSample` `:979, 999, 1019`); แสดง "กำลังโหลด..." ระหว่างรอ และ "ไม่พบตัวอย่าง" ถ้าว่าง (`:1093-1096`) **หมายเหตุ:** ตัวอย่างมาจากไฟล์โซนที่ engine โต้ตอบคำนวณตามกฎ/ค่าตั้งปัจจุบันของหน้า Rules ซึ่งอาจไม่ตรงกับตัวเลขบนการ์ด (ตัวเลขการ์ดใช้ IQR×1.5); ถ้าเรียก API ไม่ผ่าน (ไม่ OK/ผิดพลาด) รายการจะค้างที่ "กำลังโหลด..." เพราะไม่มีการตั้งค่าตัวอย่างว่าง (`:149-155`)

### 5.4 ช่อง "ค้นหาเรคคอร์ด" (พับอยู่ใน LearnMore) (`:1024-1053`)

- (1) พิมพ์ข้อความ (รหัสนักศึกษา/ชื่อวิชา/ค่าอื่น) แล้วระบบค้นให้ทันทีทุกตัวอักษร (ไม่มี debounce) (2) ค้นหาแถวในข้อมูลดิบ (3) `GET /whitebox/preview-zone/raw?limit=8&search=<คำ>` (`:1034`) ฝั่ง backend ค้นแบบ "มีข้อความนี้อยู่ในช่องใดก็ได้" ไม่สนตัวพิมพ์ (`whitebox.py:1516-1519`) (4) แสดง "พบ N แถว" (🟢 `matched_rows`) และรายการสูงสุด 8 แถวในรูป `#id · student_id · course · score=… · study_hours=… · semester` — คอลัมน์ที่แสดงฮาร์ดโค้ดตามสคีมานักศึกษา 🔴 ถ้าไฟล์เป็นสคีมาอื่นช่องเหล่านี้จะว่าง; ข้อผิดพลาดถูกกลืนเงียบ (`catch {}` `:1036`) — **ค้นจากไฟล์ที่ API ถือ ไม่ใช่จาก HDFS** และทุกครั้งที่เรียก backend คำนวณโซนใหม่ทั้งชุดและเขียนไฟล์ CSV 3 ไฟล์ซ้ำ (`whitebox.py:1498`) ซึ่งอาจช้าเมื่อไฟล์ใหญ่

## 8. สามคำตอบสั้น (สำหรับพูดกับอาจารย์)

**หน้านี้มีไว้ทำอะไร?** เป็นขั้นตอนที่ 1 ของระบบ: รับข้อมูลเข้า (ส่วนที่ใช้งานจริงคือไฟล์ CSV/Excel และตาราง PostgreSQL) แล้วโชว์ผลตรวจคุณภาพเบื้องต้น พร้อมส่งข้อมูลเข้าท่อ Spark.

**ผู้ใช้ทำอะไรได้?** เลือก/ลากไฟล์หรือกรอกข้อมูลเชื่อมต่อฐานข้อมูล → กดนำเข้า → ดูสรุปแถว/ค่าว่าง/ซ้ำ/ผิดปกติ, ดูตัวอย่างแถว, ค้นหาเรคคอร์ด, ติ๊กเลือกปัญหาที่จะนำไปสร้างกฎ, ติดตามสถานะรอบตรวจ (แท็บ API/Stream ยังเป็นการสาธิต).

**ระบบทำอะไรเบื้องหลัง?** ตรวจสิทธิ์/ขนาด/ชื่อตาราง/ไฟล์ซ้ำ → เขียนไฟล์ลง HDFS ที่ `/data/raw/<table>/<ingest_id>/` → บันทึกรอบใน Elasticsearch → สั่ง Spark Trigger Daemon เข้าคิวรัน Spark Quality Engine → เขียนข้อมูลผ่านลง `/data/active` (Delta), แถวเสียลง `/data/quarantine`, ย้ายต้นฉบับไป `/data/archive`, ให้ AI แก้ไขแถวที่ถูกกักกันอัตโนมัติ 1 รอบ แล้วอัปเดตสถานะ QUEUED→RUNNING→SUCCEEDED/FAILED.
