## ส่วนที่ 0: คำตอบสำคัญก่อนอ่านรายละเอียด (ตรวจจากโค้ด)

- **AI ตัวไหน?** ใช้ **Groq** (บริการ AI บนอินเทอร์เน็ต) ที่ `https://api.groq.com/openai/v1/chat/completions` (`dashboard_llm.py:23`) โมเดลเริ่มต้น `openai/gpt-oss-120b` (`:24`) หรือโมเดลที่ตั้งในหน้า Rules (`:78-86`) **ไม่ใช้ Ollama** (ค้นคำว่า ollama ในไฟล์ dashboard ทั้งหมดแล้วไม่พบ)
- **AI คิดตัวเลขเองไหม?** **ไม่** AI ตอบกลับเป็น "แบบแปลนแดชบอร์ด" (เรียกว่า spec = ไฟล์ JSON บอกว่ามีกราฟอะไร ใช้คอลัมน์ไหน นับแบบไหน) แล้วโค้ด Python (pandas) เป็นคนคำนวณตัวเลขจากข้อมูลจริงทั้งหมด (`dashboards.py:89-90`, `dashboard_compute.py:211-222`)
- **AI เขียน SQL ไหม?** ไม่ คอมเมนต์ในโค้ดระบุว่า "ไม่มีอะไรใน spec ถูกรันเป็นโค้ดหรือ SQL" (`dashboard_spec.py:5-6`)
- **ส่งอะไรให้ Groq?** ชื่อชุดข้อมูล + กลุ่มผู้ใช้ + ข้อความที่ผู้ใช้พิมพ์ + "โปรไฟล์คอลัมน์" (ชื่อคอลัมน์ ชนิด จำนวนค่าไม่ซ้ำ % ค่าว่าง และค่าต่ำสุด/สูงสุดของคอลัมน์ตัวเลข/วันที่) **ไม่ส่งแถวข้อมูล ไม่ส่งชื่อหมวดหมู่** (`dashboard_llm.py:120-136`) และไม่ส่งช่วงตัวเลขของคอลัมน์ที่ดูเหมือนรหัส/เบอร์/เลขบัญชี (`:110-117`) ตอนกดปุ่ม "เรียบเรียงด้วย AI" ส่งโปรไฟล์คอลัมน์ (ไม่มีค่าต่ำสุด/สูงสุด) + ชื่อตาราง + กลุ่มผู้ใช้ + ข้อความของคำแนะนำที่กฎสร้าง (มีแต่ชื่อคอลัมน์) ไม่ส่งแถวข้อมูล ไม่ส่งค่าหมวดหมู่ และไม่ส่ง widget ของคำแนะนำ การเรียบเรียงส่งโปรไฟล์โดยไม่มีค่าต่ำสุด (min) และค่าสูงสุด (max) เลย ตอนปรับแดชบอร์ดส่งเพิ่มรายการข้อความของสิ่งที่แดชบอร์ดยังขาด (`suggested_changes`) ซึ่งมีชื่อคอลัมน์ ป้ายของฟังก์ชันรวมค่า ตัวเลขเช่นเปอร์เซ็นต์ค่าว่าง และบางข้อความมีชื่อวิดเจ็ตของสเปกปัจจุบัน (ไม่มีค่าในเซลล์) เมื่อมี semantic layer โปรไฟล์ที่ส่งตัดคอลัมน์ข้อมูลส่วนบุคคลออกก่อน (เมื่ออ่าน semantic layer ได้ ถ้าอ่านไม่ได้ตัดตามกฎชื่อและธงที่กู้ได้เท่านั้น ดูข้อจำกัดใต้ส่วน "ความหมายคอลัมน์") (ทั้งตอนสร้าง ปรับ และเรียบเรียงคำแนะนำ) ตอนสร้างและปรับแดชบอร์ดโปรไฟล์ยังเติมบทบาท ชื่อที่แสดง หน่วย สกุลเงินของแต่ละคอลัมน์ (เฉพาะที่มีค่า) พร้อมรายการ metric (id ชื่อ คำอธิบาย รูปแบบ ไม่มีค่า เพิ่มเมื่อมี metric) ส่วนตอนเรียบเรียงคำแนะนำส่งแค่ชื่อคอลัมน์ ชนิด จำนวนค่าไม่ซ้ำ และ % ค่าว่าง กับข้อความคำแนะนำ ไม่มีบทบาทหรือรายการ metric ตอนกด "ให้ AI ร่าง" ความหมายคอลัมน์ ส่งชื่อชุดข้อมูล จำนวนแถว โปรไฟล์ของคอลัมน์ที่ไม่ถูกซ่อน และคำเดาจากกฎ (`hint_role`, `hint_pii`) ไม่ส่งค่าในเซลล์
- **ถ้าไม่มี Key หรือ AI ล้ม:** สร้างแดชบอร์ด "แบบกฎอัตโนมัติ" แทน (ดูหัวข้อ "ผลเมื่อ AI ไม่พร้อม") แต่การ "ปรับด้วย AI" จะใช้ไม่ได้ (ตอบ HTTP 503)
- **เก็บที่ไหน:** Elasticsearch index `sdoqap_dashboards` เก็บเฉพาะ "แบบแปลน" ไม่เก็บตัวเลขที่คำนวณแล้ว ตัวเลขคำนวณใหม่ทุกครั้งที่เปิด

- **[ตัวเลือก "ผู้ใช้แดชบอร์ด": Business User / Data Analyst / Management / ดูแลคุณภาพข้อมูล]** -> (1) เลือกกลุ่มผู้ใช้เป้าหมาย (ค่าเริ่มต้น business) กลุ่มนี้เป็นคำใบ้ของแดชบอร์ด ไม่ใช่สิทธิ์การเข้าถึง (ระบบ login ยังมีบัญชี admin เดียว) (2) -- (3) `ContextForm.jsx` ส่งไป `/generate` และ `/suggestions` เป็น `audience` เซิร์ฟเวอร์ตรวจว่าเป็น 1 ใน 4 ค่า (`AUDIENCES` ใน `dashboard_spec.py`) และใส่ในพรอมต์ให้ AI: management = KPI หัวข้อ+เปรียบเทียบ+แนวโน้ม ไม่มีตารางกว้าง / analyst = แตกมิติมากขึ้น+ตารางรายละเอียด / business = สมดุล / steward = สุขภาพข้อมูล (KPI จำนวนแถวเทียบจำนวนค่าไม่ซ้ำของคอลัมน์คีย์ จำนวนค่าว่าง ค่าต่ำสุดสูงสุด และแนวโน้มคะแนนคุณภาพเมื่อเป็นชุดผลตรวจคุณภาพ) (4) 🔴 รายการตัวเลือกฮาร์ดโค้ด ผลต่อรูปแบบแดชบอร์ดเป็น 🤖 (ถ้าใช้ AI) และ 🟡 ในโหมดกฎอัตโนมัติ (`fallback_spec` ใช้ audience แล้ว: management ไม่มีตารางและ KPI แรกเทียบรายเดือน, analyst ตารางกว้าง 12 คอลัมน์, steward ได้แดชบอร์ดสุขภาพข้อมูล) ลำดับการ์ดคำแนะนำเปลี่ยนตามกลุ่มที่เลือก และ steward ได้การ์ดสุขภาพข้อมูล (กฎ R8) ก่อน
- **[ปุ่ม "สร้างแดชบอร์ดด้วย AI"]** -> (1) กดแล้วสร้างแดชบอร์ด ระหว่างรอขึ้น "AI กำลังออกแบบแดชบอร์ด…" (2) -- (3) `generate` `DashboardBuilder.jsx:113-124` -> `POST /api/v1/dashboards/generate` body `{table_name, context, audience}` -> `generate_dashboard` `dashboards.py:85-91` (ขั้นตอนเบื้องหลังดูด้านล่าง) (4) ผลลัพธ์ `{spec, data, engine, model, warnings}` เก็บใน state `draft` แล้วไปขั้นที่ 4 และล้างตัวกรอง/ประวัติคำสั่ง/ผลเปลี่ยนแปลงเดิมทิ้ง (`:119-123`) 🤖 AI สร้าง (spec) + 🟡 (ตัวเลข)

### ขั้นตอนเบื้องหลังของการสร้าง (`POST /generate`)

1. ตรวจ `audience` (`dashboards.py:87`)
2. โหลดตารางจาก HDFS `/data/active/...` + สร้างโปรไฟล์ (`load_active_dataset` `:88`; แคช 120 วินาที เก็บได้สูงสุด 4 ตาราง `dashboard_data.py:39-40`) แล้วอ่าน semantic view ของตาราง (`_dataset` ใน `dashboards.py`: ฉบับอนุมัติ ถ้าไม่มีใช้ฉบับร่าง ถ้าไม่มีใช้กฎจากชื่อคอลัมน์) และตัดคอลัมน์ส่วนบุคคลออกจากโปรไฟล์ (`semantic_layer.apply_to_profile`) พร้อมเติมบทบาท ชื่อที่แสดง หน่วย สกุลเงิน
3. ประกอบพรอมต์ = system prompt ที่กำหนดรูปแบบ JSON/กฎ (`dashboard_llm.py:33-70`) + JSON ของ `{dataset, audience, request, profile}` (`:133-136`) และเพิ่ม `metrics` (id ชื่อ คำอธิบาย รูปแบบ) เมื่อชุดข้อมูลมี metric
4. หา API key: ค่าที่บันทึกในหน้า Rules (ES index `sdoqap_settings` สามารถปิดใช้ได้) -> ตัวแปร `GROQ_API_KEY` -> ไฟล์ `.env` (`whitebox.py:1638-1658`, `dashboard_llm.py:78-86`)
5. เรียก Groq: temperature 0.2, `max_tokens` 8192, บังคับตอบเป็น JSON, timeout 20 วินาที (`dashboard_llm.py:25, 89-107`)
6. ตรวจคำตอบด้วย `validate_spec` (ดูหัวข้อถัดไป) ถ้าไม่ผ่านจะ "ถาม AI ซ้ำ 1 ครั้ง" พร้อมบอกเหตุผลที่ถูกปฏิเสธ แต่ถ้าครั้งแรกใช้เวลาเกิน 25 วินาทีจะไม่ลองซ้ำ (`:156-173`, `RETRY_BUDGET_S` `:26`)
7. ถ้าไม่มี key / ต่อ Groq ไม่ได้ / ตอบ HTTP ไม่ใช่ 200 / ตรวจสเปกไม่ผ่านหลังลองซ้ำ -> ใช้ `fallback_spec` (แบบกฎ) แทน (`:199-209`)
8. **โค้ดคำนวณตัวเลขทุกวิดเจ็ต** ด้วย pandas (`compute_dashboard` `dashboards.py:90`)
9. ส่งกลับ `engine` = `"groq"` หรือ `"rules"`

### รั้วกันความผิดพลาดของ AI (`dashboard_spec.py` `validate_spec` `:191-216`)

- ยอมรับเฉพาะชนิดวิดเจ็ต 7 แบบ: kpi, bar, line, area, pie, donut, table (`:15`) และการคำนวณ 7 แบบ: count, count_distinct, count_missing (นับเซลล์ว่างของคอลัมน์ใดก็ได้), sum, avg, min, max (`:16`)
- คอลัมน์ที่ AI อ้างต้องมีอยู่จริงในตาราง; sum/avg/min/max ใช้ได้กับคอลัมน์ตัวเลขเท่านั้น (`:50-63`); กราฟเส้น/พื้นที่ต้องใช้แกน X เป็นวันที่หรือตัวเลข (`:120-121`)
- จำกัดขนาด: วิดเจ็ตไม่เกิน 16, ตัวกรองไม่เกิน 6, คอลัมน์ตาราง <=12, limit แท่ง <=20, วงกลม <=8, ตาราง <=200 แถว (`:11-14, 24`)
- สิ่งที่ผิดจะ "ถูกตัดทิ้งพร้อมคำเตือน" (warnings) ไม่ใช่ทำให้ล้มทั้งหมด; ถ้าไม่เหลือวิดเจ็ตใดเลยจะ error (`:206-207`)
- ตำแหน่งวิดเจ็ตบน Grid 12 คอลัมน์ ระบบจัดเองด้วย `_pack` (AI กำหนดแค่ลำดับ/ขนาด) (`:74-79, 144-153`)
- สเปกที่เบราว์เซอร์ส่งกลับมา (refine/render/save) ถูกตรวจซ้ำทุกครั้ง (`dashboards.py:60-64, 97, 111, 139`)

- **[ปุ่ม "ส่งออก CSV"]** -> (1) ดาวน์โหลดแถวข้อมูลที่แดชบอร์ดใช้คำนวณอยู่ตอนนี้ (ตัวกรองและการคลิกกราฟชุดเดียวกับบรรทัด "X จาก Y แถว" จำนวนแถวในไฟล์จึงเท่ากับ X) ให้ทีม BI ทำต่อใน Excel หรือ Power BI เป็นไฟล์แถวข้อมูลเท่านั้น ไม่ใช่ตัวเชื่อม Power BI และไม่ใช่การส่งออก spec หรือ JSON ระหว่างทำงานปุ่มกดไม่ได้และขึ้น "กำลังเตรียมไฟล์…" และกดไม่ได้ระหว่างแดชบอร์ดกำลังคำนวณตัวกรองใหม่ ถ้าชุดข้อมูลเปลี่ยนก่อนดาวน์โหลดเสร็จ ไฟล์ที่มาถึงทีหลังถูกทิ้ง ไม่ถูกบันทึก (2) ไฟล์ `<ตาราง>_<YYYYMMDD>.csv` (วันที่ตามเวลาไทย ชื่อตารางแทนอักขระที่ไม่ใช่ตัวอักษร ตัวเลข `_` `-` ด้วย `_`) UTF-8 มี BOM ให้ Excel อ่านภาษาไทยได้ หัวคอลัมน์ใช้ชื่อที่แสดงจาก semantic layer ถ้าไม่มีใช้ชื่อคอลัมน์ (ชื่อที่ซ้ำกันต่อท้ายด้วย ` [ชื่อคอลัมน์]`) เรียงคอลัมน์ตามตาราง ค่าในไฟล์เป็นค่าที่เก็บไว้ใน active layer ไม่ใช่ค่าที่แดชบอร์ดแปลงแล้ว คอลัมน์ที่เก็บเป็นข้อความ (รวมวันที่และเวลาที่เก็บเป็นข้อความ เช่น `2025-01-05 10:00:00+07:00` หรือ `unknown`) เขียนตามที่เก็บทุกตัวอักษร ไม่แปลงเป็น UTC ไม่ทิ้งค่าที่แดชบอร์ดอ่านเป็นตัวเลขหรือวันที่ไม่ได้ (เช่น `N/A`, `12A`) คอลัมน์ที่เก็บเป็นชนิดวันที่เวลาจริง ถ้าทุกค่าเป็นเที่ยงคืนเขียน `YYYY-MM-DD` ไม่งั้นเขียน `YYYY-MM-DD HH:MM:SS` ต่อด้วยเศษวินาที (เช่น `.123456`) หรือ offset (เช่น `+07:00`) เมื่อค่านั้นมี คอลัมน์ชนิดตัวเลขไม่มีรูปแบบยกกำลัง ค่าว่างเป็นช่องว่าง ค่าจริงเท็จเป็น `TRUE`/`FALSE` (3) `ExportCsv.jsx` -> `POST /api/v1/dashboards/export` body `{table_name, selections, include_personal}` -> `export_dashboard_rows` อ่านชุดข้อมูลใหม่หนึ่งครั้ง (`dashboard_data.load_active_pair` ไม่ใช้ cache 120 วินาทีของแดชบอร์ด ได้ทั้งค่าที่เก็บไว้และค่าที่แดชบอร์ดเตรียมแล้วจากการอ่านครั้งเดียวกัน) อ่าน semantic view ครั้งเดียว กรองบนค่าที่เตรียมแล้วด้วย `apply_filters` ตัวเดียวกับ `/render` (จำนวนแถวจึงเท่ากับ `rows_after_filter`) แล้วเอาแถวตำแหน่งเดียวกันจากค่าที่เก็บไว้เขียนด้วย `dashboard_export.csv_chunks` ทีละ 10,000 แถวแบบ stream ตอบ `Content-Type: text/csv; charset=utf-8` และ `Content-Disposition: attachment` ชื่อไฟล์ที่ฝั่งหน้าเว็บอ่านตาม RFC 6266 (`filename*` ก่อน) และแทน `/` กับ `\` ด้วย `_` ก่อนบันทึก (4) 🟢 แถวจริงจาก active layer
  - เซลล์ข้อความและหัวคอลัมน์ที่ขึ้นต้นด้วย `=`, `+`, `-`, `@`, tab หรือ CR ถูกเติม `'` ข้างหน้า กันสูตรทำงานเมื่อเปิดใน Excel (CSV injection) ยกเว้นเซลล์ที่เป็นตัวเลขล้วนด้วยเลข 0-9 เช่น `-12.5` (เลขอารบิกอินเดียหรือเลขเต็มความกว้างอย่าง `-١٢` ไม่นับ จึงถูกเติม `'`) คอลัมน์ชนิดตัวเลขไม่ถูกเติมเลย ข้อแลกเปลี่ยนคือ `'` มองเห็นได้ใน Excel และ Power BI สำหรับข้อความเช่นเบอร์โทรที่มีช่องว่าง `+66 81 ...` ส่วนเบอร์ที่ไม่มีช่องว่าง เช่น `+66812345678` เข้าเกณฑ์ตัวเลขล้วนจึงไม่ถูกเติม `'` และ Excel แสดงเป็นตัวเลข หัวคอลัมน์ถูกทำให้ปลอดภัยก่อนตรวจชื่อซ้ำ ป้าย `=x` กับ `'=x` จึงไม่ชนกันหลังเติม `'`
  - เกิน 1,000,000 แถวหลังกรอง (`MAX_EXPORT_ROWS` ใน `dashboard_export.py` ต่ำกว่าเพดาน 1,048,576 แถวต่อชีตของ Excel) ตอบ 413 "ข้อมูลหลังกรองมี ... แถว เกินที่ส่งออกได้ 1,000,000 แถว กรุณาเพิ่มตัวกรองแล้วลองใหม่" ข้อความ error แสดงใต้ปุ่ม
  - ทุกการส่งออก (ติ๊กหรือไม่ติ๊ก "รวมข้อมูลส่วนบุคคล") ตอบ 503 "ยังอ่านความหมายคอลัมน์ไม่ได้ จึงส่งออกไม่ได้ในตอนนี้ กรุณาลองใหม่" เมื่ออ่าน semantic layer ไม่ได้ (Elasticsearch ล่มหรือเอกสารอ่านไม่ได้ สถานะ `unavailable`) เพราะกฎจากชื่อคอลัมน์ไม่เห็นคอลัมน์ที่คนติดธงส่วนบุคคลไว้ในเอกสารเท่านั้น ข้อความคำเตือนและ log จึงบอกชื่อคอลัมน์ส่วนบุคคลให้ครบไม่ได้ ระบบไม่ส่งไฟล์ไปโดยไม่รู้ว่ามีอะไรอยู่ข้างใน (แดชบอร์ดเองยังใช้ได้)
  - ตอบ 422 "ไม่มีคอลัมน์ที่ส่งออกได้ ทุกคอลัมน์เป็นข้อมูลส่วนบุคคล" เมื่อทุกคอลัมน์ถูกซ่อนและไม่ได้ติ๊ก
  - ตรวจทุกอย่างก่อนเริ่มส่ง (รวมการสร้างตัวเขียนไฟล์) ถ้าเกิดข้อผิดพลาดหลังเริ่มส่งแล้ว (เช่น เชื่อมต่อขาด) ผ่านหน้าเว็บจะขึ้นข้อความ "ดาวน์โหลดไฟล์ไม่ครบ กรุณาลองใหม่" และไม่บันทึกไฟล์ แต่ไคลเอนต์ที่เรียก API ตรงอาจได้ไฟล์ที่ขาดท้ายโดยไม่มีข้อความเตือน
- **[ช่องติ๊ก "รวมข้อมูลส่วนบุคคล"]** -> (1) ติ๊กแล้วไฟล์ถัดไปมีคอลัมน์ส่วนบุคคลด้วย ขึ้นเฉพาะเมื่อความหมายคอลัมน์ที่บันทึกไว้ซ่อนบางคอลัมน์ ค่าเริ่มต้นไม่ติ๊ก และกลับเป็นไม่ติ๊กหลังส่งออกสำเร็จทุกครั้ง (2) เมื่อติ๊กขึ้นคำเตือนว่าไฟล์จะมีข้อมูลส่วนบุคคลจากคอลัมน์ใด และระบบบันทึกชื่อผู้ส่งออก คำเตือนมี `role="note"` และผูกเป็นคำอธิบายของช่องติ๊ก (`aria-describedby`) โปรแกรมอ่านหน้าจอจึงอ่านให้ทันทีที่ติ๊ก (3) อ่าน `hidden_columns` จาก `GET /api/v1/semantic/{table}` (อ่านไม่ได้ ช่องติ๊กไม่ขึ้น) API รับเฉพาะ JSON `true` (`StrictBool` ค่าอื่นได้ 422) ผู้ใช้ที่ login ทุกคนเลือกได้เพราะยังไม่มีระบบ role ทุกครั้งที่ไฟล์มีคอลัมน์ส่วนบุคคล API เขียน log ระดับ WARNING `Dashboard CSV export with personal columns: user=... table=... rows=... columns=...` (ชื่อคอลัมน์ ไม่มีค่าในเซลล์) การส่งออกอื่นเขียน log ระดับ INFO ตัวกรองที่อ้างคอลัมน์ซ่อนถูกข้ามเหมือน `/render` แม้ติ๊กแล้ว (4) 🟢
- **[ตารางจัดวาง Grid 12 คอลัมน์]** -> (1) ไม่มีปุ่ม (2) แต่ละวิดเจ็ตวางตามตำแหน่ง x,y กว้าง w สูง h (3) `DashboardCanvas.jsx:51-63` ใช้ CSS grid (`DashboardBuilder.css:92-96` แถวละ 72px) (4) 🟡 ตำแหน่งสุดท้ายคำนวณโดย `_pack` `dashboard_spec.py:144-153` จากลำดับ/ขนาดที่ AI เสนอ

### 5.3 วิดเจ็ตแต่ละชนิด

- **[การ์ด KPI (ตัวเลขใหญ่)]** -> (1) ไม่มีปุ่ม (2) ค่าสรุปเดียว เช่น ผลรวม/เฉลี่ย/นับ (3) `KpiCard.jsx` ค่า `value` จาก `_kpi` `dashboard_compute.py:97-109` -> `_aggregate` `:58-65` (4) 🟡 count = จำนวนแถว (หลังกรอง); count_distinct = `nunique`; sum/avg/min/max = ผลรวม/ค่าเฉลี่ย/ต่ำสุด/สูงสุดของคอลัมน์ (แปลงเป็นเลขแบบปลอดภัย ปัดทศนิยม 4 ตำแหน่ง `:24-27`) **ส่วนเลือกว่าจะนับอะไร/คอลัมน์ไหน/ชื่อการ์ด = 🤖 AI สร้าง** การแสดงผล: >=10,000 ย่อเป็น K/M, `currency` ใช้สัญลักษณ์ตามรหัสสกุลเงินของวิดเจ็ต (`$`, `฿`, `€` มาจากความหมายคอลัมน์หรือ metric ที่บันทึกไว้ คือฉบับอนุมัติ ถ้าไม่มีใช้ฉบับร่าง) ถ้าไม่มีรหัสแสดงตัวเลขเปล่า, `percent` ใส่ `%` (`utils/numberFormat.js:5-13`) การ์ดที่ใช้ `metric_id` คำนวณตามนิยาม metric (`evaluate_metric`: อัตราส่วนคำนวณตัวตั้งและตัวหารแยกกันแล้วหาร ตัวหารเป็น 0 ได้ค่าว่าง รูปแบบเปอร์เซ็นต์คูณ 100) และรูปแบบตัวเลขมาจาก semantic layer ก่อนค่าที่ AI ส่งมา ยกเว้นคอลัมน์ตัวเลขที่หน่วยเป็น `number` (หน่วยที่กฎเดาให้ยังไม่มีคนอนุมัติ หรือคนเลือกตัวเลขธรรมดา) ซึ่งใช้รูปแบบ `percent` ที่ AI ส่งมาเมื่อการรวมไม่ใช่ผลรวม เพราะผลรวมของอัตราไม่ใช่อัตรา (หน่วยเงินที่ระบุไว้ยังชนะเสมอ) ข้อจำกัด: วิดเจ็ตเงินที่คอลัมน์หรือ metric ยังไม่มีรหัสสกุลเงินในความหมายที่บันทึกไว้ (ฉบับอนุมัติ ถ้าไม่มีใช้ฉบับร่าง) จะแสดงตัวเลขเปล่า ไม่มีสัญลักษณ์เงิน ส่วนรหัสที่รูปแบบถูก (ตัวอักษร A ถึง Z สามตัว ซึ่งเซิร์ฟเวอร์ตรวจแค่นี้) แต่ไม่ใช่สกุลเงินจริง `Intl` จะแสดงตัวอักษรของรหัสนั้นนำหน้าตัวเลข เช่น `ZZZ 1,234.5`
- **[แถบ "▲/▼ x% ช่วงล่าสุดเทียบช่วงก่อน" บน KPI]** -> (1) ไม่มีปุ่ม (2) การเปลี่ยนแปลงเทียบช่วงเวลา (ขึ้นเฉพาะ KPI ที่สั่ง `compare` และข้อมูลมี >=2 ช่วงเวลา) (3) `KpiCard.jsx:5, 9-13`; คำนวณ `dashboard_compute.py:99-108` (4) 🟡 สูตร = `(ค่าช่วงล่าสุด - ค่าช่วงก่อนหน้า) / |ค่าช่วงก่อนหน้า| x 100` ปัด 1 ตำแหน่ง; "ช่วง" = วัน/สัปดาห์/เดือน/ไตรมาส/ปี ตามที่ตั้ง; เป็น null ถ้าค่าก่อนหน้าเป็น 0 สีเขียวหรือแดงตาม `higher_is_better` ของวิดเจ็ต (เช่นต้นทุนที่ลดลงเป็นสีเขียว) class `is-good` / `is-bad`
  - ข้อสังเกตจากโค้ด: เทียบ "ช่วงเวลาสุดท้ายที่มีข้อมูล" กับช่วงก่อนหน้า โดยไม่ตรวจว่าช่วงสุดท้ายครบหรือยัง (ช่วงที่ยังไม่จบอาจทำให้ค่าดูลดลง)
- **[กราฟแท่ง (Bar)]** -> (1) คลิกที่แท่งเพื่อกรองทั้งแดชบอร์ด (drill-down) (2) เปรียบเทียบค่าตามหมวดหมู่ (3) `ChartWidget.jsx:42-55` (วาดด้วยไลบรารี recharts); ข้อมูลจาก `_bar` `dashboard_compute.py:112-120` (4) 🟡 สูตร: จัดกลุ่มตามคอลัมน์ X แล้วคำนวณ (นับ/รวม/เฉลี่ย...) ต่อกลุ่ม เรียงตาม `sort` (desc/asc/x) เอา `limit` อันดับแรก (ค่าเริ่มต้น 10 สูงสุด 20); ถ้ามี `group_by` แตกเป็นหลายชุดสี (สูงสุด 8 ชุด ที่เหลือรวมเป็น "อื่นๆ" `dashboard_compute.py:17, 89-92`) และ `stacked` ซ้อนแท่ง; การเลือกกราฟ/แกน/อันดับ = 🤖 AI สร้าง

## ผลเมื่อ AI ไม่พร้อม (สรุปที่ตรวจจากโค้ด)

| สถานการณ์ | สร้างแดชบอร์ด (`/generate`) | ปรับด้วย AI (`/refine`) |
|---|---|---|
| ไม่มี Groq key (หรือปิดใช้ในหน้า Rules) | ใช้แดชบอร์ดแบบกฎ (`engine: rules`) มีป้ายแจ้ง + หมายเหตุ "ยังไม่ได้ตั้งค่า Groq API key" (`dashboard_llm.py:160-161, 199-209`) | HTTP 503 "ปรับด้วย AI ไม่ได้ตอนนี้" (`dashboards.py:100-101`) |
| ต่อ Groq ไม่ได้ / HTTP != 200 / ตอบรูปแบบอ่านไม่ได้ | แบบกฎ (`dashboard_llm.py:89-107, 199-209`) | HTTP 503 |
| AI ตอบ JSON ใช้ไม่ได้ (ลองซ้ำ 1 ครั้งแล้ว) | แบบกฎ | HTTP 422 "AI ตอบสเปกที่ใช้ไม่ได้" |

แดชบอร์ดแบบกฎ (`fallback_spec` `dashboard_llm.py`) สร้างจากชนิดคอลัมน์ ความหมายคอลัมน์ (ถ้ามี) และกลุ่มผู้ใช้ เมื่อมี metric ใน semantic layer การ์ด KPI ใช้ metric ก่อน (สูงสุด 4 ใบ) แล้วเติมด้วยตัววัดตาม "รวมแบบ" ที่บันทึกไว้ (ฉบับอนุมัติ ถ้าไม่มีใช้ฉบับร่าง) และไม่รวมหรือวาดกราฟจากคอลัมน์รหัส ค่าเริ่มต้น (business): KPI "จำนวนแถว" + KPI ผลรวมของคอลัมน์ตัวเลข 3 คอลัมน์แรก + กราฟเส้นรายเดือนตามคอลัมน์วันที่แรก + กราฟแท่งตามหมวดหมู่ที่มีค่าไม่ซ้ำมากที่สุด + โดนัทตามหมวดที่น้อยที่สุด (ถ้า <=8 ค่า) + ตาราง 8 คอลัมน์แรก + ตัวกรองหมวดหมู่ 2 ตัว/วันที่ 1 ตัว; management: เหมือนกันแต่ไม่มีตาราง และ KPI แรกเทียบรายเดือนเมื่อมีวันที่; analyst: ตาราง 12 คอลัมน์; steward: KPI จำนวนแถว, KPI ค่าไม่ซ้ำของคอลัมน์ที่น่าจะเป็นคีย์ (ค่าไม่ซ้ำ ≥ 90% ของแถว ถ้าเป็นตัวเลขต้องเป็นจำนวนเต็มแบบรหัส สูงสุด 2), KPI ค่าว่างของคอลัมน์ที่ว่างมากที่สุด 3 คอลัมน์, KPI ต่ำสุดและสูงสุดของคอลัมน์ตัวเลขที่ไม่ใช่รหัส 2 คอลัมน์ และตาราง 8 คอลัมน์ (ถ้าจำนวนแถวต่างจากค่าไม่ซ้ำของคีย์ แสดงว่ามีแถวซ้ำ หรือคีย์มีค่าว่าง เพราะการนับค่าไม่ซ้ำไม่นับเซลล์ว่าง) และเมื่อชุดข้อมูลเป็นประวัติผลตรวจคุณภาพ (`_quality_runs`) steward ได้ KPI คะแนนเฉลี่ย แถวที่ถูกกักกัน จำนวนรอบ กราฟแนวโน้มคะแนนรายวัน กราฟแท่งตารางที่คะแนนต่ำสุด โดนัทผลผ่านเกณฑ์ และตารางรอบล่าสุด ชื่อวิดเจ็ตเหล่านี้เป็น 🔴 ข้อความคงที่ แต่ตัวเลขยังคำนวณจากข้อมูลจริง 🟡 ไม่มีข้อมูลสมมติ (mock) ในหน้านี้

## ความเป็นส่วนตัวของข้อมูลที่ส่งออกไป Groq (สรุป)

| ส่งออก | ไม่ส่งออก |
|---|---|
| ชื่อตาราง, กลุ่มผู้ใช้, ข้อความที่ผู้ใช้พิมพ์ (ทั้งตอนสร้างและตอนปรับ), จำนวนแถว, ชื่อคอลัมน์ + ชนิด + จำนวนค่าไม่ซ้ำ + % ค่าว่าง, min/max ของคอลัมน์ตัวเลข/วันที่, (ตอนปรับ) สเปกปัจจุบัน (ชื่อวิดเจ็ต/คอลัมน์ที่ใช้), (ตอนกดเรียบเรียงคำแนะนำ) ข้อความคำแนะนำที่กฎสร้าง, (ตอนปรับ) ข้อความรายการสิ่งที่แดชบอร์ดยังขาด (`dashboard_llm.py:133-138`; ตอนเรียบเรียงคำแนะนำ `:310-324` ซึ่งไม่ส่ง min/max), (ตอนสร้างและตอนปรับ) บทบาท ชื่อที่แสดง หน่วย สกุลเงินของคอลัมน์ และ id ชื่อ คำอธิบาย รูปแบบของ metric, (ตอนกด "ให้ AI ร่าง") ชื่อชุดข้อมูล จำนวนแถว โปรไฟล์ของคอลัมน์ที่ไม่ถูกซ่อน และคำเดาจากกฎ `hint_role` / `hint_pii` | แถวข้อมูล, ค่าหมวดหมู่, ตัวอย่าง 20 แถวที่เห็นในขั้น "ดูข้อมูล", min/max ของคอลัมน์ตัวเลขที่ดูเหมือนรหัส (จำนวนเต็มที่ค่าไม่ซ้ำตั้งแต่ 90% ของแถวขึ้นไป หรือมี >=9 หลัก `:110-117, 120-130`), ชื่อและสถิติของคอลัมน์ที่ถูกซ่อนเป็นข้อมูลส่วนบุคคล (`hidden_columns` ของ semantic layer ซึ่งยังซ่อนตามกฎชื่อคอลัมน์แม้ Elasticsearch ล่ม) |

ข้อควรรู้: ชื่อคอลัมน์ (ยกเว้นคอลัมน์ที่ติดส่วนบุคคลซึ่งถูกตัดออก) และข้อความที่พิมพ์ถูกส่งออกจริงโดยไม่ผ่านการปิดบัง รวมถึงชื่อที่แสดง หน่วย สกุลเงิน และชื่อกับคำอธิบายของ metric ที่คนหรือ AI เขียนไว้ (ตอนสร้างและปรับ) และ `hint_role` / `hint_pii` (ตอนกด "ให้ AI ร่าง") และ Groq เป็นบริการภายนอกบนอินเทอร์เน็ต

## ข้อสังเกตที่อาจถูกถามในการนำเสนอ (ตรวจจากโค้ด)

1. AI อาจเลือก "นับอะไร" ไม่เหมาะกับความหมายของข้อมูล (เช่น รวมคอลัมน์ที่ไม่ควรรวม) แต่ตัวเลขที่ออกมาถูกต้องตามนิยามที่เลือก เพราะโค้ดคำนวณจากข้อมูลจริง ผู้ใช้ปรับด้วยคำสั่งได้
2. ระยะเวลา: Groq timeout 20 วินาที/ครั้ง (`dashboard_llm.py:25`) ถ้าต้องลองซ้ำอาจรวมเกิน 30 วินาที แต่ nginx ตั้ง `proxy_read_timeout 30s` (`services/ui/nginx.conf:21`) ขณะที่คอมเมนต์ในโค้ดเขียนว่า proxy ยอม 60 วินาที (`dashboard_llm.py:25`) จึงอาจเกิด HTTP 504 ในกรณีช้า (ยังไม่ได้รันทดสอบ ข้อนี้เป็นข้อสังเกตจากการอ่านโค้ด)
3. ข้อมูลทั้งตารางถูกโหลดเข้าหน่วยความจำของ API (pandas) ไม่ได้สุ่มตัวอย่าง (การ "สุ่ม/ตัด" มีเฉพาะ: ดูตัวอย่าง 20 แถว, เดาชนิดคอลัมน์จาก 500 ค่าแรก, ตารางแสดง <=200 แถว, ผลตรวจคุณภาพ 5,000 รอบล่าสุด)
4. ตารางที่เลือกได้มีเฉพาะชุดข้อมูลที่ผ่าน Quality Gate แล้ว (active layer) จึงไม่รวมข้อมูลที่ถูกกักกัน (quarantine)
5. ข้อจำกัดของ semantic layer ที่ควรบอกตรง ๆ (ตรวจจากโค้ด):
   - การซ่อนข้อมูลส่วนบุคคลใช้กับเส้นของแดชบอร์ดที่ผ่าน `_dataset` ใน `dashboards.py` (คำแนะนำ `suggestions`, `suggest-changes`, `rank-suggestions`, `generate`, `refine`, `render`) แต่ `GET /saved/{id}` คืนสเปกที่เก็บไว้โดยไม่ตรวจซ้ำ (อาจมีชื่อคอลัมน์ที่ภายหลังถูกติดเป็นส่วนบุคคล ชื่อเท่านั้น ไม่มีค่า) หน้าเว็บเปิดแดชบอร์ดที่บันทึกผ่าน `POST /render` ซึ่งตรวจซ้ำและตัดวิดเจ็ตที่ใช้ไม่ได้ แต่ผู้เรียก API ตรง ๆ จะได้สเปกดิบ
   - เส้นดูตัวอย่าง (`GET /datasets/{table}/preview`) ส่งทุกคอลัมน์รวมคอลัมน์ส่วนบุคคล หน้าเว็บแค่ติดป้าย "ส่วนบุคคล" ที่หัวคอลัมน์ในตัวอย่าง
   - ถ้าเอกสาร semantic layer ใน Elasticsearch เสียหรืออ่านไม่ได้ (`semantic.load_view` ครอบทั้งการอ่านและการ `resolve`) ทั้งเส้นของแดชบอร์ดและ `GET /api/v1/semantic/{table}` ถอยไปใช้กฎจากชื่อคอลัมน์ (สถานะ "unavailable" ไม่ใช้ความหมายหรือ metric ที่อนุมัติไว้) แทนที่จะตอบ 500 และยังซ่อนคอลัมน์ที่ชื่อบ่งว่าเป็นส่วนบุคคล บวกคอลัมน์ที่ส่วน `approved` หรือ `draft` ของเอกสารที่เก็บไว้ติด `pii: true` ไว้ (กู้จาก `content_json` ดิบทีละส่วน) ถ้าเอกสารเสียจนอ่านธงไม่ได้ ธงของคอลัมน์ที่ชื่อไม่บ่งว่าเป็นส่วนบุคคลจะหาย; `POST`/`PUT`/อนุมัติยังอ่านเอกสารที่เสียไม่ได้ (500) จนกว่าจะซ่อมเอกสารใน Elasticsearch
   - Spark และ Gold ยังไม่อ่าน semantic layer (ไม่ปิดบังข้อมูลส่วนบุคคลตอน export และไม่คำนวณ metric ล่วงหน้า) ใช้เฉพาะหน้า Create Dashboard
   - การส่งออก CSV ของหน้านี้ (`POST /export`) ใช้ view เดียวกับแดชบอร์ด คอลัมน์ส่วนบุคคลไม่อยู่ในไฟล์เว้นแต่ผู้ใช้ติ๊ก "รวมข้อมูลส่วนบุคคล" และตัวกรองที่อ้างคอลัมน์ซ่อนถูกข้ามเหมือน `/render` แต่เส้นดาวน์โหลดของหน้า Data Export (`GET /api/v1/export/raw|active|quarantine/{table}` และ `/preview/{layer}/{table}` ใน `data_export.py`) ยังส่งทุกคอลัมน์รวมคอลัมน์ส่วนบุคคล และไม่ต้อง login (ตรวจจากโค้ด ณ 2026-10-08) ข้อมูลส่วนบุคคลจึงยังออกทางนั้นได้ เป็นช่องว่างที่รู้อยู่และยังไม่ได้แก้ มีงานแยกรอรับไปทำ
   - การส่งออกแบบติ๊ก "รวมข้อมูลส่วนบุคคล" ไม่มีการตรวจสิทธิ์เพิ่ม ผู้ใช้ที่ login ทุกคนเลือกได้ และ log บอกแค่ผู้ส่งออก ตาราง จำนวนแถว กับชื่อคอลัมน์ส่วนบุคคล (ไม่มีค่า) log อยู่ใน stdout ของ container ยังไม่เก็บเป็น audit trail ถาวร
   - ไฟล์ส่งออกทั้งก้อนอยู่ในหน่วยความจำของ browser ตอนดาวน์โหลด (fetch แล้วสร้าง blob) ฝั่ง API ส่งเป็นชิ้นละ 10,000 แถว แต่แต่ละคำขอส่งออกอ่านตารางใหม่ทั้งตารางและถือไว้สองชุดในหน่วยความจำ (ค่าที่เก็บไว้และค่าที่เตรียมแล้ว) ระหว่างส่งออก
   - วิดเจ็ตเงินที่ยังไม่มีรหัสสกุลเงินในความหมายที่บันทึกไว้ (ฉบับอนุมัติ ถ้าไม่มีใช้ฉบับร่าง) แสดงตัวเลขเปล่าไม่มีสัญลักษณ์ (รหัสสามตัวอักษรที่ไม่ใช่สกุลเงินจริงขึ้นเป็นตัวอักษรของรหัสนำหน้าตัวเลข) และการคำนวณ metric ใช้ข้อมูลทั้งชุดในหน่วยความจำของ API (ไม่มี pushdown) จึงช้าเท่ากับการคำนวณแดชบอร์ดปัจจุบันในชุดข้อมูลใหญ่

## Flow ตั้งแต่ต้นจนจบ (ลำดับเหตุการณ์)

1. เปิดหน้า `/dashboard-builder` (ต้อง login: `App.jsx:102` ห่อด้วย `RequireAuth`) -> ขั้นที่ 1 โหลดรายการชุดข้อมูล `GET /datasets` (ข้อมูลจริงจาก HDFS + ES) และรายการแดชบอร์ดที่บันทึก `GET /saved` (จาก ES) 🟢
2. ผู้ใช้เลือกตาราง -> กด "ถัดไป" (ขั้นเปลี่ยนใน UI เท่านั้น)
3. ขั้นที่ 2: `GET /datasets/{ตาราง}/preview` + `GET /api/v1/semantic/{ตาราง}` -> เห็นสถิติ ความหมายคอลัมน์ แผง metric และตัวอย่าง 20 แถว แก้แล้วบันทึกร่างหรืออนุมัติได้ และกด "ให้ AI ร่าง" ได้ 🟢🟡🤖
4. ขั้นที่ 3: พิมพ์ความต้องการ + เลือกกลุ่มผู้ใช้ -> กด "สร้างแดชบอร์ดด้วย AI" -> `POST /generate`
5. Backend: โหลดข้อมูล+โปรไฟล์ -> ส่งโปรไฟล์ (ไม่มีแถวข้อมูล) + คำขอให้ Groq -> ได้ spec JSON 🤖 -> `validate_spec` ตรวจ whitelist/จัดวาง -> (ถ้า AI ไม่พร้อม ใช้ `fallback_spec`) -> pandas คำนวณตัวเลขทุกวิดเจ็ต 🟡 -> ส่ง `{spec, data, engine, warnings}`
6. ขั้นที่ 4: วาด KPI/กราฟ/ตารางตาม spec และตัวเลขที่คำนวณ + ตัวกรอง + แถบสถานะ engine
7. กรอง/คลิกกราฟ (drill-down) -> `POST /render` (ไม่ใช้ AI คำนวณใหม่ด้วย pandas ตามตัวกรอง)
   - กด "ส่งออก CSV" -> `POST /export` ด้วยตัวกรองชุดเดียวกัน -> ได้ไฟล์ CSV ของแถวหลังกรอง (ไม่ใช้ AI ไม่มีคอลัมน์ส่วนบุคคลถ้าไม่ติ๊ก)
8. พิมพ์คำสั่งปรับ -> `POST /refine` -> AI แก้ spec -> ตรวจ -> คำนวณใหม่ -> แสดง "สิ่งที่เปลี่ยน" (โค้ดเทียบสเปก)
9. กด "บันทึก" -> `POST /saved` (หรือ `PUT /saved/{id}` ถ้าเคยบันทึก) -> เขียนลง Elasticsearch `sdoqap_dashboards` (เก็บ spec + ประวัติคำสั่ง + ข้อความที่ผู้ใช้พิมพ์ ไม่เก็บตัวเลข)
10. กลับขั้นที่ 1 -> เห็นรายการที่บันทึก -> "เปิด" (`GET /saved/{id}` + `POST /render` คำนวณใหม่จากข้อมูลปัจจุบัน) หรือ "ลบ" -> "ยืนยันลบ" (`DELETE /saved/{id}`)

## สรุปท้ายหน้า

**หน้านี้มีไว้ทำอะไร?** ให้ผู้ใช้เลือกชุดข้อมูลที่ผ่าน Quality Gate แล้วพิมพ์ความต้องการเป็นภาษาธรรมชาติ เพื่อได้แดชบอร์ด (KPI กราฟ ตาราง ตัวกรอง) ที่ปรับแต่งและบันทึกไว้เปิดใช้ซ้ำได้

**ผู้ใช้ทำอะไรได้?** เลือกตาราง ดูโครงสร้าง/ตัวอย่างข้อมูล พิมพ์ความต้องการและเลือกกลุ่มผู้ใช้ สร้างแดชบอร์ดด้วย AI กรอง/คลิกกราฟเพื่อเจาะลึก ส่งออกแถวที่กรองแล้วเป็นไฟล์ CSV สั่ง AI ปรับแก้ บันทึก เปิด และลบแดชบอร์ดที่บันทึกไว้

**ระบบทำอะไรเบื้องหลัง?** อ่านข้อมูลจาก HDFS/Elasticsearch ด้วย pandas ส่งเฉพาะโปรไฟล์คอลัมน์ (ไม่ใช่แถวข้อมูล) ให้ Groq ออกแบบแบบแปลน JSON แล้วโค้ดตรวจ whitelist และคำนวณตัวเลขทั้งหมดเอง (ถ้า AI ไม่พร้อมใช้แบบกฎแทน) และเก็บเฉพาะแบบแปลนใน Elasticsearch `sdoqap_dashboards`
