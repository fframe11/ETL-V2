# สรุปภาพรวม UI ทั้งระบบ SDOQAP (สำหรับนำไปพูดกับอาจารย์)

> ที่มา: อ่านโค้ดจริงทีละหน้า (Frontend → API → Backend → Spark/Elasticsearch/HDFS) แล้วแยกป้ายกำกับแหล่งข้อมูลทุกจุด
> รายละเอียดทีละปุ่ม/ทีละส่วนอยู่ในไฟล์ 01–07 (ลิงก์ท้ายเอกสาร) ไฟล์นี้คือ "ฉบับย่อสำหรับพูด"
> หมายเหตุวิธีตรวจ: อ่านโค้ดอย่างเดียว **ยังไม่ได้รันระบบ** ตัวเลขที่เห็นบนจอจริงขึ้นกับข้อมูลที่โหลดอยู่ในระบบ ณ ตอนนั้น

## ป้ายกำกับที่ใช้ทุกไฟล์

| ป้าย | ความหมาย |
|---|---|
| 🟢 | ข้อมูลจริงจาก Backend (ดึงจาก Elasticsearch / HDFS / บริการจริง) |
| 🟡 | ข้อมูลที่คำนวณจากข้อมูลจริง (มีสูตรระบุ) |
| 🔴 | Mock / Static / ค่าคงที่ฮาร์ดโค้ด |
| ⚪ | UI ที่มีแต่ยังไม่ได้เชื่อมระบบจริง |
| 🤖 | ส่วนที่ AI (LLM) เป็นผู้สร้าง |

## 1. ระบบนี้ทำงานอย่างไร (พูดได้ใน 30 วินาที)

```
ผู้ใช้ (เบราว์เซอร์)  →  nginx  →  FastAPI (services/api)  →  Elasticsearch (เก็บผล/ตั้งค่า)
                                          │                  HDFS (เก็บไฟล์ raw / active / quarantine)
                                          └─ สั่งงาน ──→  Spark (services/spark) ตรวจและคัดแยกข้อมูล
```

- **ขั้นตอนหลัก 4 ขั้น (เมนู "ขั้นตอนการทำงาน"):** 1) นำเข้าข้อมูล → 2) ตั้งกฎคุณภาพ → 3) รัน Pipeline คัดแยก → 4) ส่งออกข้อมูลที่ผ่านการคัดกรอง
- **เมนู "ติดตามและตรวจสอบ":** Dashboards, Create Dashboard, Query & Metrics, Catalog, Audit Trail
- หน้าเว็บ **ไม่ได้ประมวลผลข้อมูลเอง** แค่เรียก API แล้วแสดงผล ตัวตรวจคุณภาพจริงคือ Spark

## 2. ข้อควรรู้ที่สำคัญที่สุดก่อนนำเสนอ

ระบบมี **สองเอนจินที่แสดงผลคล้ายกัน** ซึ่งตรงนี้อาจทำให้ถูกถามได้

| เอนจิน | ทำงานที่ไหน | ใช้ข้อมูลอะไร | หน้าที่ใช้ |
|---|---|---|---|
| **Spark Pipeline (ของจริง)** | services/spark | ไฟล์ที่ผู้ใช้อัปโหลด/ดึงจากฐานข้อมูล → HDFS | Home (KPI), Dashboards, Query & Metrics, Catalog, ประวัติการรัน |
| **pandas "whitebox engine" (เดโม)** | ภายใน API (`whitebox.py`) | ไฟล์ CSV นักเรียนตัวอย่าง `dirty_dataset.csv` (~10,100 แถว) | ครึ่งบนของ Jobs & Pipelines, การ์ดผลตรวจใน Ingestion, การ์ดกฎใน Expectations, Audit Trail, Technical Cockpit ใน Dashboards |

ถ้าถูกถามว่า "ตัวเลขนี้มาจาก Spark หรือเปล่า?" ให้ดูตารางรายหน้าด้านล่าง

## 3. รายหน้า: ใช้ทำอะไร / จริงแค่ไหน

### Home
- **ใช้ทำอะไร:** หน้าแรก สรุปคะแนนคุณภาพ สถานะบริการ และทางลัดไปแต่ละขั้น
- 🟢 3 การ์ดตัวเลข (Avg Quality Score, Records Checked, Quarantine Rate) มาจาก ES index `sdoqap_quality_runs` ผ่าน `/kpi/stats` รวม **ทุกรอบ ทุกตาราง ตลอดเวลา**
- 🟢 Live Infrastructure Connections (11 บริการ) = เช็กว่า "พอร์ตเปิดอยู่ไหม" ไม่ได้แปลว่าบริการทำงานถูกต้อง
- 🔴/🟡 **Live Ingestion Channels ไม่ใช่ข้อมูลการนำเข้าจริง** เป็นแค่สถานะพอร์ต Kafka/Postgres/API คำว่า "Ingesting/Idle/Active" เป็นข้อความคงที่
- ⚠️ ถ้า API ล้ม Quarantine Rate โชว์ `0.000%` ขณะอีกสองใบโชว์ `---`

### Data Ingestion
- **ใช้ทำอะไร:** นำเข้าข้อมูลเข้าระบบ
- 🟢 **ทำงานจริงครบถึง HDFS/Spark มี 2 ช่องทางเท่านั้น:** ไฟล์ (CSV/Excel ≤200MB) และฐานข้อมูล (PostgreSQL อ่านอย่างเดียว ≤1,000,000 แถว) ข้อมูลลง `/data/raw/<ตาราง>/<ingest_id>/` แล้ว Spark ตรวจต่อ
- ⚪ แท็บ **API** เป็นโหมดสาธิต (`simulated: True` ใน `whitebox.py`) ไม่ได้ดึง API จริง
- ⚪ แท็บ **Stream** ช่อง Kafka ไม่ผูกกับระบบจริง ปุ่มไปสั่งดึง Reddit ด้วยค่าตายตัว
- 🟡 การ์ด "ผลตรวจข้อมูล" คำนวณด้วย pandas บนสคีมานักเรียน ไม่ใช่ผล Spark

### Expectations & Alerts
- **ใช้ทำอะไร:** ตั้งกฎคุณภาพข้อมูลก่อนรัน
- 🔴 การ์ดกฎด้านบน (วงแหวน 95/99/99) ฮาร์ดโค้ด/เดโม pandas
- ⚪ **ค่าที่บันทึกได้แต่ Spark ไม่เคยอ่าน:** freshness threshold, `ai_advisor.model`, แฟล็ก `enabled` ของการตรวจหลัก
- 🤖 ข้อเสนอกฎจาก AI: Groq → Ollama → heuristic ตามลำดับ (ปกปิดคอลัมน์ ID ก่อนส่ง) ถ้าไม่มีข้อมูลจะแสดง **ตัวอย่าง 3 รายการ** (ป้าย "ตัวอย่าง")
- ⚪ **การแจ้งเตือน:** ไม่มี UI ตั้ง Slack/Email/Webhook ไม่มีโค้ดส่งอีเมล ตัวส่ง Slack/LINE มีแต่ไม่มี token ตั้งไว้ จึงแค่พิมพ์ log

### Jobs & Pipelines
- **ใช้ทำอะไร:** ดูผลคัดแยก Clean / Review / Quarantine และประวัติการรัน
- 🟡 ส่วนบน (funnel, 3 การ์ด, ตารางแถว) เป็น **เอนจิน pandas** ปุ่ม "รัน Pipeline" คำนวณใหม่ ไม่ได้สั่ง Spark
- 🟢 Spark จริงมีแค่ **Clean (`/data/active`) และ Quarantine (`/data/quarantine`)** โซน Review มีเฉพาะในเอนจิน pandas
- 🟢 ตารางประวัติการรัน มาจาก ES จริง (มีปุ่ม Retry ที่ยิง `/pipeline/retry`)
- ⚪ ปุ่ม "แจ้งแก้ต้นทาง" แค่พลิกค่า true/false ไม่ได้สร้าง ticket

### Workspace Exports
- **ใช้ทำอะไร:** ดาวน์โหลดข้อมูลหลังคัดกรอง
- 🟢 ดาวน์โหลดได้เฉพาะ **CSV** (ไม่มี Excel/Parquet/JSON) ไม่พบเพดานขนาดไฟล์
- 🔴 ค่าสำรอง 9400/100/600/93.1 ฮาร์ดโค้ด และไปอยู่ในชื่อไฟล์ด้วย
- 🔴 ชื่อไฟล์ "certified_gold_clean.csv" เป็นชื่อคงที่ ชั้น Gold จริงคือ 4 index สรุปใน ES จาก `spark_gold_layer.py` (ประมาณการ $11/แถว)

### Dashboards
- **ใช้ทำอะไร:** ภาพรวมคุณภาพข้อมูลและผลกระทบทางธุรกิจ
- 🟢/🟡 คะแนนคุณภาพ, availability, freshness, ประวัติรัน, พยากรณ์ (linear regression) มาจากข้อมูลจริง
- 🔴 **Sell-In/Sell-Out เป็นตัวอย่าง 7 วันฮาร์ดโค้ด** (`analytics.py:799-807`)
- 🔴 **ตัวเลขเงินทั้งหมดเป็นสมมติฐาน** ($2/แถว, 5% × $50, อัตรา 36.5 บาท/ดอลลาร์ คงที่)
- ⚪ ตัวกรอง Time Range ไม่ทำอะไร ตัวกรอง Business Area ใช้ได้เฉพาะ "sales"
- ⚠️ ไม่แสดง error ของ API: เห็นเป็นค่าเก่า หรือ `---`/0 ถ้าไม่มีข้อมูลโชว์ Data Health 100% "Good"

### Create Dashboard
- **ใช้ทำอะไร:** สร้างแดชบอร์ดจากตารางที่เลือกด้วย AI
- 🤖 AI (Groq เท่านั้น) **เสนอแค่โครง (spec)** ไม่คำนวณเลข ไม่เขียน SQL โค้ดตรวจ spec ตามรายการที่อนุญาต (7 ชนิดวิดเจ็ต, 6 การรวมค่า)
- 🟢 **ตัวเลขทุกตัวคำนวณด้วย pandas** จากข้อมูลจริง
- 🟢 ความเป็นส่วนตัว: ส่ง Groq แค่ชื่อตาราง ข้อความที่ผู้ใช้พิมพ์ และโปรไฟล์คอลัมน์ (ไม่ส่งแถวข้อมูล)
- 🟡 ไม่มี key/Groq ล้ม → สร้างด้วยกฎสำรอง (ยังใช้ข้อมูลจริง) แต่ "ปรับแต่ง" จะ error 503
- บันทึกใน ES `sdoqap_dashboards` เก็บเฉพาะ spec ตัวเลขคำนวณใหม่ทุกครั้งที่เปิด

### Query & Metrics
- **ใช้ทำอะไร:** แนวโน้มคุณภาพและคำแนะนำ
- 🟡 พยากรณ์ 7 วันแรกมาจากการถดถอยเชิงเส้น วัน 8–30 **สร้างในเบราว์เซอร์** (ชันขึ้นเสมอ)
- ⚪ **ไม่มีช่อง query จริง** ที่ชื่อเมนูว่า "Query" แค่ช่องค้นหาฝั่งเบราว์เซอร์
- ⚪ ปุ่ม "นำไปใช้" แค่บันทึก timestamp ไม่ได้ปรับกฎจริง
- ⚪ ช่อง SLA target เปลี่ยนแค่การแสดงผล

### Catalog
- **ใช้ทำอะไร:** อนุมัติ/ปฏิเสธการเปลี่ยนโครงสร้างตาราง (schema drift) **ไม่ใช่รายการตารางหรือพรีวิวข้อมูล**
- 🟢 ข้อเสนอเกิดจาก Spark ตรวจพบ drift → เขียน ES → "อนุมัติ" เขียนทะเบียนสคีมาใน ES และ `schema_registry.json` ซึ่ง Spark อ่านในการรันครั้งถัดไป
- ⚠️ ป้าย SEV แสดง "SEV 1" ตลอด (UI อ่านฟิลด์ `severity_score` แต่ Spark เขียน `drift_severity`)
- ⚠️ ช่อง Primary Key/Partition Date ถูกเติมค่าไว้ล่วงหน้า ถ้ากดอนุมัติโดยไม่แก้ อาจเขียนทับค่าจริงของบางตาราง
- "ปฏิเสธ" แค่เปลี่ยนสถานะ ทั้งที่ข้อความใน modal บอกว่าข้อมูลจะถูก quarantine

### Audit Trail
- **ใช้ทำอะไร:** ดูเหตุผลของระบบทีละขั้น (สำรวจ → กฎ → ผลลัพธ์)
- 🔴/🟡 **เป็นเดโม pandas ในตัว API บน CSV นักเรียนตัวอย่าง ไม่ใช่หลักฐานจาก Spark** ไม่มี LLM ในหน้านี้
- 🔴 ตารางข้อมูลประชากร (Table A) เป็นข้อมูลสุ่มสังเคราะห์
- 🔴 ค่าฮาร์ดโค้ด: match confidence 96.0, Post-Clean Quality 100.0, แบนเนอร์ "SLA COMPLIANCE VERIFIED" แสดงเสมอ
- ⚠️ การรันขั้นที่ 4 เขียนทับไฟล์ CSV ที่หน้า Export/Pipeline/Ingestion/Rules อ่านอยู่

### Learn & Architecture, Login, เมนูด้านข้าง
- Learn & Architecture: **เนื้อหาคงที่ทั้งหน้า** ไม่เรียก API
- Login: แอดมินคนเดียว ตรวจกับ env `ADMIN_USERNAME`/`ADMIN_PASSWORD` คุกกี้ HttpOnly ลงลายเซ็น HMAC อายุ 12 ชม. ออกจากระบบแค่ลบคุกกี้
- เมนูด้านข้าง: จุดสถานะบริการใช้ `/services/status` เดียวกับ Home
- ⚠️ Badge "รอ" ที่ Expectations & Alerts อาจนับจากตัวอย่างฮาร์ดโค้ด 3 รายการ (ตรวจยืนยันแล้ว: `dynamic_rules.py:454-465` ส่ง `is_example` แต่เมนูอ่านแค่ `count`)

## 4. ข้อควรระวังที่อาจถูกถาม (ความปลอดภัย/ความถูกต้อง)

- **endpoint อ่านข้อมูลจำนวนมากไม่ตรวจ session ฝั่ง backend** (เช่น `/services/status`, `/kpi/stats`, ดาวน์โหลด/พรีวิว Export, `/rules/*`) การป้องกันอยู่ที่ฝั่ง React เท่านั้น
- Groq API key เก็บเป็นข้อความธรรมดาใน ES index `sdoqap_settings`
- ปุ่มถังขยะในหน้า Rules ลบข้อมูล HDFS/ES จริงถาวร
- Saved dashboards ไม่มีการแยกเจ้าของ/สิทธิ์
- `seed_es.py` สามารถเขียนทับ ES ด้วยข้อมูลทดสอบ → **ก่อนเดโม ให้เช็กว่าข้อมูลที่โหลดอยู่คืออะไร**

## 5. ประโยคแนะนำสำหรับพูด

- "ส่วนที่ทำงานครบ end-to-end ด้วย Spark จริงคือ: อัปโหลดไฟล์/ดึงจาก PostgreSQL → HDFS → Spark ตรวจและแยก Clean/Quarantine → บันทึกผลใน Elasticsearch → แสดงที่ Home, Dashboards, Catalog"
- "ส่วนเดโมเพื่ออธิบายตรรกะ (whitebox) ใช้ pandas กับชุดข้อมูลนักเรียน ไม่ได้ผ่าน Spark"
- "AI ในระบบมี 2 งาน: เสนอกฎคุณภาพ และสร้างโครงแดชบอร์ด AI ไม่เคยคำนวณตัวเลข ตัวเลขมาจากโค้ดเสมอ"
- "ตัวเลขทางการเงินเป็นการประมาณจากสมมติฐานที่ตั้งไว้ในโค้ด ไม่ใช่ต้นทุนจริงขององค์กร"
