# รายงาน Transform: กฎทำงานยังไง และทำให้เป็น White Box

## งานนี้ตอบอะไร

โจทย์จากเพื่อน (คัดลอกตามที่ได้รับ):

> Transform
> ส่วนที่ 1 อธิบายกฎ ต้องตอบ 4 ข้อ
> -ตั้งกฎไปทำไม แต่ละกฎกันปัญหาอะไร
> -ผู้ใช้นำข้อมูลเข้าแล้วตั้งค่ากฎ ค่านั้นถูกส่งไปไหน
> -ตัวเลขในกฎถูกเอาไปคำนวณยังไง ตัดสินว่าแถวไหนผ่านหรือไม่ผ่าน
> -หลังตรวจตามกฎแล้ว ข้อมูลไปต่อที่กระบวนการไหน
>
> ส่วนที่ 2 วิเคราะห์ Transform ว่าควรปรับอะไร และควรเน้นอะไร

ข้อกำหนดเพิ่มจากเพื่อน 2 ข้อ:

1. **"กฎ" หมายถึงทั้งสองชุด:** การ์ด 3 ใบบนหน้า Rule (ช่วงคะแนน / ห้ามซ้ำ / ค่าผิดปกติ) **และ** กฎรายตารางในตั้งค่าขั้นสูง ("รวมเลย")
2. **ส่วนที่ 2 ต้องหาจุด black box ในหน้าที่เกี่ยวกับ Transform และเสนอวิธีทำให้เป็น white box "โดยไม่ใช่วิธีการเขียนอธิบายเพิ่มหรือเนื้อหาให้อ่านลงในเว็บ"**

รายงานนี้เป็น **เอกสารอย่างเดียว** ไม่มีการแก้โค้ดของระบบ และไม่มีการเปลี่ยนค่าในระบบระหว่างเก็บหลักฐาน

## คำตอบสั้น 4 ข้อ (ส่วนที่ 1)

**ข้อ 1: ตั้งกฎไปทำไม แต่ละกฎกันปัญหาอะไร**

- การ์ด: คะแนนที่เป็นไปไม่ได้/ว่าง, แถวซ้ำ, ค่าเรียนที่ผิดปกติ ([รายละเอียด](01-interactive-rules.md#q1))
- Spark: ลบซ้ำ, คีย์หลักว่าง, ค่าว่างทุกคอลัมน์, ชนิดข้อมูล, วันที่ว่าง, ค่าผิดปกติ IQR และ Z-score ([รายละเอียด](02-spark-table-rules.md#q1))

**ข้อ 2: ตั้งค่าแล้ว ค่าถูกส่งไปไหน**

- การ์ด: ส่งไป api ทันทีทุกครั้งที่แก้ เก็บในหน่วยความจำและไฟล์ แล้วคำนวณใหม่ทั้งไฟล์ ปุ่ม "บันทึกกฎ" แค่ส่งซ้ำ ([รายละเอียด](01-interactive-rules.md#q2))
- Spark: บันทึกลง `rules_config.json` และ Elasticsearch ทันที แต่มีผลเฉพาะรอบที่รันครั้งถัดไป Spark อ่าน Elasticsearch ก่อนไฟล์ ([รายละเอียด](02-spark-table-rules.md#q2))

**ข้อ 3: ตัวเลขในกฎถูกเอาไปคำนวณยังไง**

- การ์ด: ลำดับจริงคือ ซ้ำ → ว่าง/นอกช่วง → ค่าผิดปกติ (รั้ว Tukey = Q3 + k × IQR) ตัวอย่าง: Q1 = 3, Q3 = 8, รั้วบน k = 3.0 คือ 23.0 ชั่วโมง ([รายละเอียด](01-interactive-rules.md#q3))
- Spark: ลบซ้ำ → ตรวจแถวทีละข้อ → IQR → Z-score แล้วเทียบคะแนนกับเกณฑ์ ตัวอย่าง: `grocery_sales` 557/561 = 99.287% เทียบเกณฑ์ 90.0 ([รายละเอียด](02-spark-table-rules.md#q3))

**ข้อ 4: หลังตรวจแล้ว ข้อมูลไปต่อที่ไหน**

- การ์ด: ติดป้าย 3 คอลัมน์แล้วแยกเป็น 3 ไฟล์ Clean / Review / Quarantine ไปที่หน้า Jobs & Pipelines และ Workspace Exports ไม่แก้ค่าในข้อมูล ([รายละเอียด](01-interactive-rules.md#q4))
- Spark: แถวที่ผ่าน `MERGE` เข้าตาราง `active` สะสม แถวที่ไม่ผ่านต่อท้ายตาราง quarantine ตามรอบ คะแนนต่ำกว่าเกณฑ์แจ้งเตือน ตั้งแต่เกณฑ์ขึ้นไปเรียก Gold layer ([รายละเอียด](02-spark-table-rules.md#q4))

## สรุปส่วนที่ 2 ใน 1 หน้าจอ

**จุด black box: 30 จุด** แบ่งเป็น Data Ingestion 5, การ์ด 3 ใบ 11, กฎรายตาราง Spark 8, Jobs & Pipelines 5, Workspace Exports 1

**ควรปรับอะไร (เรียงตามลำดับ)**

| ลำดับ | สิ่งที่ควรปรับ | ปิด BB |
|---|---|---|
| 1 | ใบบันทึกการรัน (manifest) ของทั้งสองเอนจิน แสดงค่าที่ใช้จริงเทียบกับค่าที่ตั้ง (ต้องซ่อม BB-18 พร้อมกัน) | 02, 17, 19, 21, 23, 24, 27, 30 |
| 2 | กราฟการกระจายพร้อมเส้นรั้วที่เลื่อนตาม k ได้ | 09, 16 |
| 3 | ร่าง → เห็นผลต่าง → ยืนยัน พร้อมเลขเวอร์ชันชุดกฎ | 06, 13, 14, 22 |
| 4 | เหตุผลรายแถวแบบแยกช่อง + กดตัวเลขแล้วเห็นแถว | 11, 25, 26, 29 |
| 5 | เอาของปลอมออก (วงกลม 95/99/99, ป้าย `> 12.0h`, ช่องไม่มีผล 5 ช่อง, ปุ่มเชื่อมต่อที่ไม่ได้ต่อ, สถานะสำเร็จที่ไม่จริง) | 03, 07, 08, 20 |
| 6 | แสดงคีย์และชุดข้อมูลที่ใช้จริง + จับคู่คอลัมน์ตอนอัปโหลด | 01, 04, 12, 15 |
| 7 | แผนภาพไหลตามลำดับตรวจจริง | 10, 28 |
| 8 | รายการชุดข้อมูลที่นำเข้า | 05 |

**ควรเน้นอะไร:** (1) ตามรอยได้ตลอดสาย ค่ากฎ → ตัวเลข → แถว → ไฟล์ (2) ตัวเลขหนึ่งตัว มีแหล่งเดียว (3) ไม่มีช่องที่ตั้งแล้วไม่มีผล (4) สองเอนจินที่พฤติกรรมต่างกัน ต้องแสดงตัวตนของแต่ละอันตรงๆ (5) บันทึกสิ่งที่รันจริง ไม่ใช่สิ่งที่ตั้งไว้

**สิ่งที่พิสูจน์ด้วยการรันจริงและน่าจะเป็นประเด็นสำคัญสำหรับเพื่อน**

- เกณฑ์คุณภาพแบบ adaptive **ไม่เคยทำงานจริง** ในระบบที่ deploy อยู่ ทุกรอบใช้ค่าฐาน 90.0 เพราะคอนเทนเนอร์ Spark ไม่มีตัวแปร `ELASTICSEARCH_URL` (BB-18)
- ฟอร์มกฎ Spark มี 8 ช่อง **ใช้ตัดสินจริง 3 ช่อง** (BB-20)
- เลือกคีย์ที่ไม่มีในไฟล์ หรืออัปโหลดไฟล์ที่ไม่มีคอลัมน์ `semester` แล้ว "แถวซ้ำ" เพิ่มจาก 30 เป็น 213 แถว โดยป้ายยังเขียนคีย์เดิม (BB-12, BB-13)
- บนหน้า Rule วงกลมตายตัว 95 / 99 / 99 ขัดกับตารางใต้การ์ดที่คำนวณจริง 93.7 / 97.1 / 98.1 (BB-08)
- ตัวคูณ k เปลี่ยนจาก 3.0 เป็น 1.5 แล้วจับแถวชุดเดียวกัน (20 แถว) บนไฟล์ทดสอบ ผู้ใช้จึงไม่เห็นว่า k ทำอะไร (BB-09)

**คำถามที่ควรยืนยันกับเพื่อน**

1. ผลงานรอบนี้คือรายงานข้อเสนอ หรือต้องลงมือแก้ระบบด้วย
2. เมื่อซ่อมเกณฑ์ adaptive ให้ทำงานจริง จะ **จำกัดเกณฑ์ไว้ไม่ให้สูงกว่าค่าฐาน** หรือรับพฤติกรรมเดิมของสูตร (`gov_data` จะได้เกณฑ์ 100.0 และตารางที่ต่ำคงที่จะหยุดถูกเตือน)
3. ไอคอน `?` และแบนเนอร์ที่เคยเพิ่มไว้ (เป็นข้อความ) จะเก็บไว้หรือเอาออกเมื่อทำแบบใหม่แล้ว
4. จุดไหนที่เพื่อนเห็นว่าเป็น black box แต่ไม่อยู่ในรายการ 30 จุดนี้

## ข้อมูลที่ใช้ทดสอบ

- **ฝั่งการ์ด:** `sample_data/student_scores_sample.csv` 1,030 แถว (นักเรียน 250 คน) ผลที่คาดด้วยกฎเริ่มต้น: Clean 915 / Review 20 / Quarantine 95 ตรงกับผลรันจริง ผลทั้ง 10 สถานการณ์อยู่ที่ `evidence/interactive-scenarios.json`
- **ฝั่ง Spark:** ผลรันจริงใน Elasticsearch ของระบบนี้ สามตาราง: `gov_data` (86 รอบ ใช้ดูเกณฑ์ adaptive), `grocery_sales` (7 รอบ มีแถวกักกันจริง), `benchmark_test` (28 รอบ คะแนนต่ำกว่าเกณฑ์)
- **หมายเหตุ:** ใน Elasticsearch มีเอกสารผลรันตัวอย่างจาก `api/seed_es.py` ปนอยู่ รายงานใช้เฉพาะเอกสารที่มีฟิลด์ `effective_quality_threshold` ซึ่งมีแต่เอนจิน Spark ที่เขียน
- ผลคำนวณด้วยมือทั้งหมดของฝั่ง Spark: `evidence/spark-adaptive-threshold-worked.txt`

## วิธีรันหลักฐานซ้ำ

ทุกคำสั่งรันจากรากของ repo ใน Git Bash และไม่เปลี่ยนค่าในระบบ

**ฝั่งการ์ด** (รันบนสำเนาชั่วคราว ไม่แตะชุดข้อมูลและสถานะที่ใช้อยู่):

```bash
MSYS_NO_PATHCONV=1 docker compose cp sample_data/student_scores_sample.csv api:/tmp/tr_sample.csv
PYTHONIOENCODING=utf-8 MSYS_NO_PATHCONV=1 docker compose exec -T api python - < docs/transform-report/tools/capture_interactive.py > docs/transform-report/evidence/interactive-scenarios.json
```

**ฝั่ง Spark** (อ่านอย่างเดียว): ดึงจำนวนรอบต่อตาราง และเกณฑ์ที่บันทึกไว้ต่อตาราง

```bash
ES_PASS=$(MSYS_NO_PATHCONV=1 docker compose exec -T api printenv ELASTICSEARCH_PASSWORD | tr -d '\r')
curl -s -u "elastic:$ES_PASS" "http://localhost:9200/sdoqap_quality_runs/_search" -H "Content-Type: application/json" -d '{"size":0,"aggs":{"t":{"terms":{"field":"table_name.keyword","size":20},"aggs":{"thr":{"terms":{"field":"effective_quality_threshold","size":10}}}}}}'
```

**ตรวจการอ้างอิงโค้ดของรายงาน:**

```bash
PYTHONIOENCODING=utf-8 python docs/whitebox-report/tools/check_citations.py docs/transform-report/*.md
```

รายละเอียดคำสั่งดึงประวัติรอบของแต่ละตาราง และการรันฟังก์ชันคำนวณเกณฑ์ในคอนเทนเนอร์ `spark-master` อยู่ใน `evidence/spark-adaptive-threshold-probe.txt`
