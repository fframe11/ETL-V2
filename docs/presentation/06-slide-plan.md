## ส่วน A — อ่านให้เข้าใจก่อน (5 นาที)

### A1. ระบบนี้ทำอะไร ใน 5 บรรทัด
1. รับข้อมูลเข้ามา (ไฟล์ / API / ฐานข้อมูล / สตรีม) แล้วเก็บสำเนาดิบไว้ใน HDFS (`/data/raw`)
2. Spark อ่านข้อมูลดิบ ผ่าน 21 ขั้น (จัดโครงสร้าง → ทำความสะอาด → ตรวจความผิดปกติ → แยกโซน → วัดผล)
3. แถวที่ผ่านไปที่ **active** (โซนที่ใช้งานได้) แถวที่ไม่ผ่านไปที่ **quarantine** (โซนกักกัน) พร้อมเหตุผลทุกแถว
4. ผลของแต่ละรอบ (จำนวนแถว เวลา เหตุผลที่กักกัน) บันทึกใน Elasticsearch
5. คนใช้ข้อมูลจาก active ต่อ เช่น Create Dashboard, export CSV, วิเคราะห์คะแนน

### A2. คำศัพท์ที่ต้องอธิบายได้

| คำ | ความหมายแบบคนทั่วไป | ตัวอย่างในงานนี้ |
|---|---|---|
| Ground truth | เฉลยที่รู้ล่วงหน้าว่าแถวไหนผิดและผิดเพราะอะไร | `ground_truth.csv` 10,100 แถว |
| Quarantine | โซนกักกัน แถวที่ไม่ผ่านไปอยู่ที่นี่ ไม่ถูกลบ | 630 แถว |
| Active | โซนข้อมูลสะอาดที่ผู้ใช้ปลายทางใช้ | 9,370 แถว |
| Recall | ในแถวผิดจริงทั้งหมด ระบบจับได้กี่ % | 700 / 700 = 100% |
| Precision | ในแถวที่ระบบจับ มีกี่ % ที่ผิดจริง | 700 / 730 = 95.89% |
| False positive (FP) | แถวที่ถูกต้อง แต่ระบบจับผิด | 30 แถว |
| False negative (FN) | แถวผิดที่ระบบจับไม่ได้ | 0 แถว |
| IQR | ค่านอกช่วงที่คำนวณจากควอร์ไทล์ ตัวคูณ 3.0 = เข้มกว่า 1.5 | ลด FP จาก 101 เหลือ 30 |
| Z-score | ห่างจากค่าเฉลี่ยกี่เท่าของส่วนเบี่ยงเบนมาตรฐาน เกิน 3σ = ผิดปกติ | ต้นเหตุของ FP ทั้ง 30 แถว |
| Delta MERGE | เขียนลงตารางโดยจับคู่ตามคีย์ มีแล้วอัปเดต ไม่มีแล้วเพิ่ม | โหลดเข้า active |
| Idempotent | รันซ้ำแล้วผลเท่าเดิม ไม่ซ้ำซ้อน | quarantine ลบตาม `ingest_id` แล้วเขียนใหม่ |
| Conservation | แถวเข้า = แถวออกรวมทุกที่ ไม่มีแถวหายเงียบ | 10,100 = 9,370 + 630 + 100 |
| Medallion | แบ่งชั้นข้อมูล Bronze (ดิบ) → Silver (สะอาด) → Gold (สรุป) | raw/archive = Bronze, active = Silver, `sdoqap_gold_*` = Gold |

### A3. สี่เรื่องที่ต้องเข้าใจให้ชัดก่อนพูด (กรรมการถามบ่อยและเป็นจุดอ่อน)

1. **10,100 → 10,000 → 9,370 + 630**
   ไฟล์ต้นทางมี 10,100 แถว ระบบตัดแถวคีย์ซ้ำ 100 แถวทิ้งก่อน (ไม่เข้า quarantine) เหลือ 10,000 แล้วแบ่งเป็น 9,370 สะอาด + 630 กักกัน ตัวเลข `total_records` ในระบบคือ 10,000 ไม่ใช่ 10,100 ถ้าไม่อธิบายเรื่องนี้ กรรมการจะเห็นว่าแถวหาย 100 แถว
2. **ค่าว่างถูกจับทางอ้อม**
   กฎของตารางนี้เติม `score = 0` ให้ค่าว่างก่อน แล้ว IQR จับเลข 0 เป็นค่านอกช่วง เหตุผลที่บันทึกจึงเขียน `score=0.0` ไม่ใช่ "missing" ผลลัพธ์ถูก (300 แถวถูกกักกัน) แต่กลไกไม่ตรงกับที่คนคาดหวัง
3. **False positive 30 แถวคือนักศึกษาจริง**
   21 แถวคือคนที่ได้ 37–49 คะแนน ซึ่งไม่ใช่ข้อมูลผิด ผลต่อเนื่องคือรายชื่อ "นักศึกษาที่ต้องติดตาม" เหลือ 5 จาก 28 คน
4. **Spark กับเอนจินโต้ตอบให้ผลต่างกัน**
   Spark: 9,370 / 630 · เอนจินโต้ตอบ: 9,400 สะอาด / 100 รอตรวจ / 600 กักกัน ต้องบอกชื่อเอนจินทุกครั้งที่โชว์ตัวเลข ในเอกสารนี้ใช้ Spark ทั้งหมด

### สไลด์ 06 — Data Utilization Outcome (เกณฑ์ 6 · 5 คะแนน)
