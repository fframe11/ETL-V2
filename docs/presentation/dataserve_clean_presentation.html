DataServe: Enterprise Data Operations & Quality Assurance Platform

แพลตฟอร์มบริหารจัดการและประกันคุณภาพข้อมูลระดับองค์กรบน Modern Medallion Lakehouse

ปัญหาของ Data Pipeline ทั่วไป

เมื่อพบข้อมูลผิดพลาด ระบบส่วนใหญ่มักจะลบแถวทิ้งไปอย่างเงียบๆ (Silent Drop) ทำให้ยอดรวมทางธุรกิจไม่ตรง หรือไม่ก็ปล่อยข้อมูลผิดพลาดหลุดรอดไปทำลายรายงานของผู้บริหาร

หัวใจสำคัญของ DataServe

ทำงานบนหลักการ Zero Silent Drop ข้อมูลที่มีปัญหาทุกแถวจะถูกคัดแยกเข้าโซนกักกันอย่างโปร่งใส พร้อมระบุสาเหตุอย่างละเอียด เพื่อให้ยอดรวมกระทบยอดได้ครบ 100%

Zero Silent Drop

ไม่ลบข้อมูลทิ้งแม้แต่แถวเดียว ทุกข้อผิดพลาดมีที่ไปและสามารถตรวจสอบย้อนกลับได้เสมอ

Dual-Zone Lakehouse

แยกข้อมูลสะอาด 100% (Silver Active) ออกจากข้อมูลกักกัน (Silver Quarantine) บน Delta Lake อย่างเด็ดขาด

Closed-Loop Healing

ผูกเหตุผล reject_reason แจ้งเตือนผ่าน Webhook กลับไประบบต้นน้ำให้แก้ไขได้ตรงจุด

Slide 02 · Architecture End-to-End Pipeline

End-to-End Data Pipeline Architecture

เส้นทางการเดินทางของข้อมูล 5 ช่วงหลัก จากแหล่งกำเนิดสู่การใช้งานจริง

1. Multi-Source Ingestion

รองรับทั้งไฟล์ (CSV, Excel), ฐานข้อมูล (PostgreSQL), REST API, และสตรีมมิง (Kafka)

2. Raw Landing (Bronze Layer)

บันทึกข้อมูลดิบดั้งเดิม 100% ลง HDFS เพื่อความโปร่งใสและสอบทานย้อนกลับได้

3. Spark Quality Engine

ประมวลผลและคัดกรองข้อมูลระดับแถวบน Apache Spark แบบ In-Memory ต่อเนื่อง

4. Dual-Zone Storage (Silver Layer)

• Active Store (Delta Lake): ข้อมูลสะอาดที่ผ่านเกณฑ์ 100% พร้อมใช้งาน
• Quarantine Store (Delta Lake): ข้อมูลที่มีปัญหา พร้อมคอลัมน์ระบุเหตุผล reject_reason

5. Downstream & Closed-Loop

ส่งต่อข้อมูลสะอาดให้ Create Dashboard และส่ง Webhook แจ้งเตือนระบบต้นน้ำอัตโนมัติ

Slide 03 · Normalization Smart Type Promotion

Structural Normalization & Smart Type Promotion

ปรับโครงสร้างข้อมูลสู่มาตรฐาน ป้องกันปัญหาข้อมูลสูญหายตั้งแต่ก้าวแรก

Column Sanitization & Dynamic PK
  • Column Sanitization: ตัดช่องว่าง ลบอักขระพิเศษ และจับคู่ชื่อคอลัมน์ให้ตรงตาม Schema กลาง
  • Dynamic row_hash: สร้างรหัสแถวอัตโนมัติด้วย MD5 สำหรับตารางที่ไม่มีคีย์หลัก เพื่อใช้ในการเชื่อมโยงข้อมูลขนาดใหญ่
  • Schema Drift Governance: หากต้นทางเปลี่ยนโครงสร้าง คอลัมน์ใหม่จะอัปเดตให้อัตโนมัติ ส่วนคอลัมน์หายจะส่งเข้าโซนตรวจสอบ
Smart Type Promotion (ป้องกัน Data Loss)
ในระบบทั่วไป หาก Schema กำหนดเป็นจำนวนเต็ม (Integer) แต่มีค่าทศนิยมปนเปื้อน ข้อมูลมักจะกลายเป็นค่าว่าง (Null) หรือถูกปัดทิ้ง
ตัวอย่าง: คอลัมน์ระบุเป็น Integer แต่ข้อมูลส่งมา "1500.75" ระบบสแกนพบทศนิยม ──► ปรับชนิดเป็น Double อัตโนมัติ ผลลัพธ์: รักษาค่า 1500.75 ไว้ได้ครบถ้วน ไม่กลายเป็นค่าว่าง!
Slide 04 · Cleansing Deduplication Buddhist Era Normalization

Data Cleansing, Deduplication & Normalization

กำจัดความซ้ำซ้อน แปลงเวลาสู่สากล และจัดหมวดหมู่อย่างเป็นระเบียบ

DEDUPLICATION
ตัดแถวซ้ำ 2 ชั้น

เปรียบเทียบตามคีย์หลักและเรียงตามเวลา เก็บเฉพาะข้อมูลเวอร์ชันล่าสุด ส่วนแถวซ้ำใช้ Left Anti-Join สกัดส่งเข้า Quarantine

BUDDHIST ERA
แปลง พ.ศ. เป็น ค.ศ.

ตรวจจับปี พ.ศ. อัตโนมัติ หากพบปีมากกว่า 2500 จะหักลบด้วย 543 และปรับเข้าสู่มาตรฐานสากล ISO YYYY-MM-DD

CATEGORIZATION
จัดหมวดหมู่ข้อมูล

ดึงพจนานุกรมคำสำคัญจาก Elasticsearch มาจัดกลุ่มสินค้าหรือข้อความเข้าหมวดหมู่มาตรฐาน โดยไม่ต้องแก้ไขโค้ดโปรแกรม

Input: "21 ก.ค. 2569" หรือ "21-07-2569" ──► ตรวจพบปี 2569 (> 2500) ──► หักลบ 543 ──► "2026-07-21" (ISO-8601) Input: ข้อมูลส่งซ้ำ 2 แถว ──► ตรวจสอบคีย์หลัก ──► เก็บแถวล่าสุดไว้ใน Active, ส่งแถวซ้ำไป Quarantine
Slide 05 · Rules & Stats Tukey IQR Fences Gaussian 3-Sigma

Business Rules & Advanced Statistical Anomaly Detection

ผสานกฎขอบเขตธุรกิจเข้ากับแบบจำลองสถิติขั้นสูง เพื่อดักจับข้อมูลผิดธรรมชาติ

EXPLICIT BOUNDS
กฎขอบเขตธุรกิจ

ตรวจสอบขอบเขตค่าที่ธุรกิจกำหนดตายตัว เช่น คะแนนสอบต้องอยู่ในช่วง 0 ถึง 100 แถวที่หลุดช่วงจะถูกระบุ out_of_range_score

STATISTICAL FENCE
Tukey IQR Fences

คำนวณควอร์ไทล์หาช่วงปกติ ช่วยดักจับค่าสุดโต่งที่ผิดธรรมชาติ เช่น ชั่วโมงเรียน 48 ชม./สัปดาห์ แม้ไม่ติดลบแต่เป็นไปไม่ได้จริง

UNSUPERVISED
Gaussian 3-Sigma

ตรวจจับค่าที่เบี่ยงเบนเกิน 3 เท่าของส่วนเบี่ยงเบนมาตรฐาน สำหรับข้อมูลที่มีการแจกแจงแบบปกติ เพื่อความปลอดภัยสูงสุด

[ กฎธุรกิจ ] คะแนนสอบหลุดช่วง: score = -10 หรือ 145 ──► กักกันทันที เหตุผล: "out_of_range_score" [ กฎสถิติ ] ชั่วโมงเรียนผิดธรรมชาติ: study_hours = 48 ชม. ──► กักกันทันที เหตุผล: "outlier_details"
