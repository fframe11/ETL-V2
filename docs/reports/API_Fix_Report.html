4. รายละเอียดการแก้ที่สำคัญ

F-1 · รหัสผ่าน Elasticsearch รั่วทาง /api/v1/services/status

สาเหตุ
โค้ดประกอบ URL เป็น http://elastic:<password>@localhost:9200 เพื่อใช้เป็นลิงก์ ทั้งที่ endpoint นี้เปิดสาธารณะ (หน้า login อ่านไปแสดงสถานะ)
วิธีแก้
URL เป็น http://localhost:<ES_HOST_PORT> ไม่มีข้อมูลรับรอง รูปแบบ {status, url} เหมือนเดิม UI ใช้เฉพาะ status
พิสูจน์

ควรทำต่อ

F-5 · trust-check ตัดสินด้วยเกณฑ์ที่ผิด

สาเหตุ
lineage.py อ่านเกณฑ์จาก ../../../spark/rules_config.json ซึ่งใน container กลายเป็น /spark/rules_config.json (ไม่มี ไฟล์จริงอยู่ที่ /opt/spark-apps) จึงใช้ 90 เสมอ ขณะที่ engine ใช้เกณฑ์รายตาราง (เช่น 97) ผลคือคะแนน 90.8 ถูกตอบ "ปลอดภัย" ทั้งที่เกณฑ์จริงคือ 97
วิธีแก้
ลำดับการหาเกณฑ์: (1) effective_quality_threshold ที่ engine บันทึกไว้ใน run ล่าสุด (2) กฎของตารางทับ _default จาก rules registry ใน Elasticsearch (3) 90.0 เป็นทางเลือกสุดท้าย รองรับทั้งรูป {"base_value": n} และตัวเลขเดี่ยว
พิสูจน์
ตั้งเกณฑ์ 97 แล้ว retry ได้ quality_threshold: 97.0, is_safe_to_consume: false, HALT_INGEST, เหตุผล "Quality score 90.80% is below threshold 97.0%"
ข้อสังเกต
หลังเปลี่ยนเกณฑ์ ค่าที่แสดงจะเปลี่ยนเมื่อมี run ครั้งถัดไป เพราะคะแนนของ run เดิมถูกตัดสินด้วยเกณฑ์ตอนนั้น

วิธีแก้
ฟังก์ชัน _records_json_safe ใช้ to_json(date_format="iso") ใช้กับ layer active, quarantine, reddit และ raw

F-12 · ลบตารางแล้วข้อมูลและบันทึกบางส่วนค้าง

สาเหตุ
engine ย้ายไฟล์ raw ไป /data/archive/<table>/<ingest_id> หลัง run สำเร็จ แต่โค้ดลบล้างแค่ raw, active, quarantine และไม่แตะ sdoqap_runs

F-20 · อัปโหลดจากหน้า Ingestion (API: /whitebox/upload-csv, /whitebox/state, /whitebox/benchmark)

ไฟล์ที่มีคอลัมน์นักศึกษาถูกเขียนทับที่ dirty_dataset.csv ซึ่งเป็นชุดประเมินที่ใช้เป็นเกณฑ์ (ground truth, benchmark, test) ผลคือ 10,100 แถวเหลือ 13 แถว
วิธีแก้ (API)

F-8 · การบันทึกกฎและไฟล์ rules_config.json

สาเหตุ
Elasticsearch (sdoqap_rules_registry) เป็นแหล่งจริง แต่ทุกครั้งที่บันทึก API เขียนไฟล์ใหม่ทั้งไฟล์จาก Elasticsearch ทำให้คอมเมนต์หาย ค่าที่แก้ในไฟล์ย้อนกลับ และตารางที่มีแต่ใน ES โผล่เพิ่ม และการลบตารางลบเอกสารใน ES ก่อน แล้วโหลดกฎจาก ES จึงไม่เจอตารางและข้ามการลบบล็อกในไฟล์
วิธีแก้
_save_rules_config(config, tables=[...]) อัปเดตเฉพาะตารางที่ระบุ ทั้งไฟล์และ registry (ใช้ใน PUT /rules, อนุมัติข้อเสนอ AI, มาตรฐานข้อมูล, ลบตาราง) rollback ไม่ส่ง tables จึงเขียนทั้งไฟล์ตามเดิม การลบตารางลบบล็อกในไฟล์เสมอ และจัดรูปแบบไฟล์ให้ตรงกับที่ API เขียน (ข้อมูลเหมือนเดิม)
พิสูจน์
บันทึกกฎของตารางทดสอบ ไฟล์เพิ่ม 6 บรรทัด ลบ 0 บรรทัด หลังลบตารางไฟล์เหมือน git ทุกไบต์

  • Rebuild image: docker compose up -d --build api ui (ทำแล้วบนเครื่องนี้ สภาพแวดล้อมอื่นต้องทำเอง)
