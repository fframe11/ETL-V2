งานแบ่งเป็น 4 แผนตามผลรีวิวระบบ ETL และเกณฑ์การให้คะแนน (CLO5 55% และ CLO6 15%) โดยไม่แตะระบบ Dashboard (หน้า Dashboards/Query & Metrics, analytics.py, Gold layer, Grafana, Kibana — ย้ายโฟลเดอร์ได้แต่ไม่แก้เนื้อหา)

4. Activity ของเส้นทาง ETL หลังแก้

ผู้ใช้/API        ตรวจสิทธิ์ → ตรวจชื่อตาราง → อ่านข้อมูล (จำกัดขนาด/allowlist/read-only)
                  → checksum ซ้ำ? (ตอบ duplicate) → ตรวจคีย์หลักตาม registry
                  → เขียน HDFS /data/raw/<t>/<ingest_id>/ → สร้างสถานะ QUEUED
Trigger daemon    ตรวจ secret → คิวต่อตาราง (FIFO) → spark-submit --ingest-id
Spark (21 stage)  lock+heartbeat → schema_align → schema_drift → auto_clean → validation
                  → dedup → standardize → range_rules → anomaly (IQR/Z/induced)
                  → quarantine_assembly → column_filter
                  → เขียน quarantine (idempotent) → Delta MERGE active
                  → distribution → breakdown → copdq → freshness → quality_score
                  → ai_advisory → operational_impact → report (ES)
หลังรัน           archive raw → (ถ้ามี quarantine) auto-remediation + ตรวจซ้ำ
                  → ตั้งสถานะสุดท้ายหนึ่งครั้ง: SUCCEEDED / FAILED / SKIPPED

7. สิ่งที่ทำต่างจากแผน และข้อจำกัดที่ทราบ

ต้องรู้ก่อนนำไปใช้
  • การนำเข้า HDFS/Spark ไม่มีฟอร์มในหน้า UI: ฟังก์ชัน handleCsvSubmit/handleApiSubmit/handleRdbmsSubmit ในหน้า Ingestion ไม่ถูกเรียกเลย ฟอร์มทุกแท็บเรียกแค่เอนจินโต้ตอบ จึงสร้าง hook/component แสดงสถานะรอบ (RunStatusLine) ไว้แต่ยังไม่ต่อเข้าหน้านี้
  • สถานะ SUCCEEDED มาเร็วเกินไปในร่างแรก: ตรวจพบตอน e2e แล้วแก้ให้ daemon ตั้งสถานะสุดท้ายหนึ่งครั้งหลังจบ remediation และการตรวจซ้ำ
  • ข้อความ log ของ daemon ต้องคงเดิม: หน้า Ingestion อ่านสถานะจากข้อความใน log จึงคงถ้อยคำเดิมไว้
  • ค่า IQR: ตั้ง 3.0 ตามแผน (ชั่วคราวเคยคงไว้ 1.5) และเก็บผลเปรียบเทียบทั้งสองค่าเป็นหลักฐาน
  • เอนจินโต้ตอบ: ประเมินใน workspace ชั่วคราว เพื่อไม่ทับชุดข้อมูลและ state ที่ API ใช้อยู่ เอนจินนี้ยังใช้สถานะชุดเดียวร่วมกันทุกผู้ใช้
  • เทสต์ API 1 ข้อแก้ค่าที่คาด: test_multi_table_preview จาก 10,000 เป็น 9,980 ตาม generator ที่เว้นทุก 500 คน ส่วนไฟล์ dirty_dataset.csv ที่ API ใช้อยู่เป็นชุดตัวอย่าง 1,030 แถว ต้อง mount ชุดต้นฉบับตอนรันเทสต์
  • ยังไม่ได้ตรวจบน GitHub Actions: job ใหม่ทั้ง 3 ตัวรันได้ในเครื่องเท่านั้น; ollama ขึ้น unhealthy ตามเดิมเพราะ image ไม่มี curl
  • CLO6 (15 คะแนน) รายงานเป็นคำอธิบายนวัตกรรมที่มีอยู่แล้ว ยังไม่มีการวัดว่านวัตกรรมแต่ละตัวช่วยได้กี่ %
